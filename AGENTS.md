# DoL UI project rules

- Before edits, read the relevant current source and [3.0 baseline boundaries](docs/STONE_FREE_3.0_BASELINE.md), plus the applicable [current scope](docs/STONE_FREE_V1.md). Historical experiments are evidence with a scope and date, not the current plan.
- Follow Scoped Done and Risk-Proportional Validation: define the task's delivery and acceptance, reuse valid evidence, and keep untested coverage separate from unfinished work. Documentation-only rules need link/consistency checks, not new game or full build runs.
- For README, Release Notes, Changelog, announcements and user explanations, start from verified facts, commits, changes and limitations. Use available `prp-technical-writing`, then `humanizer`, as needed; do not enable them for every task, install them automatically or claim an invocation that did not happen. Final text must preserve technical conclusions, commands, paths, Unknown and validation scope; experiments remain experiments.
- Keep current rules/code/Skill/configuration as the default reference. Preserve old designs and completed experiments with source, date, result and whether to continue; reuse existing project reports. `current/archive/experiments/artifacts` describes responsibilities, not a directory migration instruction or a new memory platform.
- Release packages serve current use: retain current code, Skill/docs where applicable, necessary resources and licenses/notices; inspect the actual dependency/file list and exclude internal experiments, obsolete plans, private tests, raw audits and temporary files. Preserve valuable history in the source repository or linked archives. Do not remove needed files solely because of their directory name or change existing packaging paths for the example layout.
- Auxiliary writing, archive and delivery rules do not alter the original game's state/event/business ownership or the current UI Runtime/API. Respect the task's execution and publication scope; recording these rules does not authorize push, Release, gameplay or data changes.
