## #41 · 谁控制画面，谁释放资源

天气提供者持有目标天气和一份粒子种子几何。消费者分别取得租约，最后一个画面退出才释放这份几何。每个 Host 挂载自行持有颜色过渡、绘制层和指针捕获。交互开始时从屏幕上当前的变换取值，将位置控制权从 WAAPI 交给指针；松手再交还给回弹。切换场景会撤销上一代指针，保留当前画面，再按新目标继续。颜色由 WAAPI 推进，降水层由自己的绘制回调推进。减少动态时降水定格。

**独立接入。** 使用发行版 StoneFreeHost、现有独立工作台 StoneFreeWorkspace、提供能力的 Host5Atmosphere 和使用能力的 Host5Observatory 四个 ZIP。Windows Edge 中性页按各包 boot 清单加载真实脚本和样式。观测台只调用 Host 的命令和视图，未安装 DoLGameUI。工作台直接挂载一份画面，观测台在自己的视图中再挂一份。隐藏第一份后，第二份仍可切雨；恢复、关闭和重开后各有正确的当前画面，焦点回到工作台入口，Host 诊断错误为零。该检查未经过游戏 ModLoader 的导入流程。[打包和复验](workspace-weather/README.md)

**等画面对照。** Edge 159、480 × 240、DPR 1，固定 36 个雨点与 36 片雪、相同位置和混合权重，分四个新页面按 Canvas / SVG / SVG / Canvas 顺序采样。固定帧两边各有 2,754 个前景像素，没有像素的任一通道相差超过 24。每窗 60 次采样，绘制调用的 JS 提交时间 P95 分别约 0.1 / 0.2 / 0.2 / 0.1 ms。绘制层 DOM 分别有 1 和 75 个节点；整页 JS 堆快照约 1.79–1.80 MB 和 2.08–2.09 MB。四窗共 240 个 rAF 间隔中没有超过 50 ms 的样本。首轮像素工具缺少 Pillow，现直接在浏览器解码截图。此项只测中性页与一种图案，不能据此判定游戏帧时、触屏输入延迟、GPU 内存或最终后端。[复跑脚本](compare.mts)

本轮采用 GSAP context 所示的按所有者回收思路，原型把释放登记在已有 Host 挂载上。共享素材可以缓存，卸载时机取决于还有哪些消费者在用。若引入视频，会按视频提交帧回调接入，不强制跟随粒子时钟。尚未选择 Pixi 或视频后端。[GSAP context](https://gsap.com/docs/v3/GSAP/gsap.context%28%29/) · [PixiJS 资源缓存与卸载](https://pixijs.com/8.x/guides/components/assets) · [视频帧回调](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)

## #42 · 宏渲染与活节点是两条边界

固定 DoL 0.5.12.13 / Loader 2.101.1 HTML 中，SugarCube 创建侧栏外壳；UIBar 更新时将 StoryCaption 渲染到 `#story-caption`。原作者 CE 1.20.4 的规则在这份原文中唯一命中并插入条件宏。维护版 rebuild.30 的同一替换只保留原条件。两份包的注入证据各自独立。

原型只认领外层布局。它在已有节点上加自己的样式标记，关闭时撤掉；原节点、已注册事件和宏输出归原作者。中性浏览器页加载了哈希固定的 rebuild.30 侧栏 JS，用受控的 Macro、状态和 jQuery 接口执行其真实 CEstatebox 处理函数。接管前、接管中与退出后各点击一次，真实按钮状态按预期改变。切换布局期间宏只运行一次，焦点和当时的按钮对象保持。还验证了节点替换、竞争、失效句柄和不支持的外壳回退。原作者规则是静态替换验证，尚未走真实 Loader。[输入身份、复验与边界](sidebar/README.md)

## 接续判断

后续的[真实 Loader 核对](REAL-LOADER.md)已覆盖独立分包导入、工作台替换、侧栏折叠、真实切页和原作者 CE 状态栏按钮。可选的 CE 菜单图标仍缺启用该入口的真实配置。特效下一轮应选择一种确有美术价值的效果，对照现有后端与 GPU 或预渲染路径，并测真实输入到显示。工作台现支持[退场中反向与降级](REAL-LOADER.md#关闭中途重开)，Windows 已验。视频解码和 Android 表现待验。Host 只管理 UI 能力和相关资源，Mod 调度及底层性能工作沿用各项目的归属。

### Host 5.0 能力地图 · 后续研究输入

Host 首先提供可复用的 UI 能力，再考虑集中哪些实现。独立 Mod 应能单独安装 Host，用自己的素材和交互制作界面。以下六个观察角度共同指导原型选择；是否新增接口或进入版本排期，由两个消费者的实际需求与收益决定。当前交付继续按既定顺序推进。

| 能力 | 研究方向与已有依据 |
| --- | --- |
| Effect | 消费者提供素材和效果定义，尝试把序列帧、纹理图集或视频与实时粒子、光影、遮罩组合。先复用慢云与实时层对照；视频解码和可编程 Shader 按可见收益、帧耗与释放成本取舍。ComfyUI 只用于离线制作素材。[组合场景](composition/README.md) |
| Motion | 研究同一时间线上的并行、串行、缓动和轨道所有权。优先验证中断、反向、手势接管时位置连续；弹簧和共享元素过渡由操作原型决定。[可反向轨道与预算](panel-budget/README.md) |
| Material | 让消费者选择或叠加 Acrylic、发光、金属、折射，并能独立释放。已有局部 Acrylic 可作对照；液态玻璃保留为可选实验，各 Mod 自定画风。[局部材质切片](panel-budget/material/README.md) |
| Environment | 天气是首个使用者。由外部适配天气或昼夜，转换成光照、雾量、降雨等连续参数，供局部与全局效果采样。沿用乌云、环境光与预渲染素材，维持移除水珠的决定。已有中途接入试验区分了共享时间和各自绘制。[共享天气样本](effects/LATE-JOIN.md) |
| Theme | 组合色、语义色、局部覆盖及可复用字体和纹理。用已有组合主题与本地 TTF 检验能力，Soft & Wet 默认沿用黑灰 Acrylic。WOFF2 与纹理按后续使用场景评估。[设置、Hub 和字体回执](../../docs/HANDOFF.md) |
| Surface | 负责区域、图层、裁剪、输入与焦点。原版侧栏由适配器认领，保留旧 Mod 的节点、事件和回退路径；侧栏和天气的业务语义留在各自消费者。[侧栏适配证据](sidebar/README.md) |

**建议的两个组合原型（待验证）**

1. **官方侧栏。** 从晴天逐渐转为阴雨，在面板展开中途拖回。记录天气相位是否连续、面板能否从当前坐标接管；在同一次转场中读正文、点击按钮，分别关闭玻璃和动效后重复操作。已有单项回执可作为对照，组合场景仍需实际操作。
2. **独立 Mod。** 在只有 Host 的页面挂载面板，使用独立素材、配色和交互动效。沿用同一套时间采样、图层合成、资源租约及降级机制，独立接管或反向播放；卸载时检查本方图层、轨道和持有的资源都已释放，仍在使用共享资源的参与者继续工作。接入方只依赖表面、控制与资源生命周期接口，渲染库留给实现选择。

Sticky Fingers 负责加载和通用生命周期，The Hand 负责游戏运行热点，Gold Experience 负责研发验证。公司 Mac 的研究使用中性夹具。

### 5.0 后续计划 · 外观自定义

以下两个切片独立排期，当前 #41 手势验收优先。

- **Host 组合主题。** 用户可选预设，或手选底色、强调色、点缀色。由 Host 派生文字、表面、交互和反馈状态所需的语义色。实时并排预览当前与候选在主界面、侧边栏、弹窗及悬浮星上的效果；进阶选项允许按区域覆盖，未覆盖区域继续继承。验收时让 Soft & Wet 和一个独立 Host 消费者同时切换，检查文字对比、错误提示与普通强调的辨识度，以及清除覆盖后能否恢复继承。
- **本地 TTF 导入。** 提供选择本机字体、预览、应用和恢复默认的完整操作。用包含中文缺字的字体检查逐字回退，确认图标保留原字形；关闭重开后核对所选字体和默认恢复结果。字体字节与偏好分开保存。文件注入用于确定性验证，真机文件选择器另外验收。用户导入的字体仅供本机使用，发行包不收录字体文件。

**组合主题首片（Mac，中性页面）。** 本地 Vite 入口 `/prototypes/host5/theme/` 并排显示草稿和两位参与者；加 `?solo` 从启动起仅挂载独立检查器。研究提供者复用既有纯调色函数，以 Host Source 提供已应用的调色板；草稿留在预览节点。应用事件仅提示重新读取，消费者经自己的绑定从同一来源取得颜色。运行 `node prototypes/host5/theme/check.mts`。Chrome 157 下，两种入口的青灰底色、正文、点缀、强调、强调上文字和错误色的计算样式逐项一致。移除工作台后，原检查器仍可切回石墨灰。未加载正式 UI 入口。后续正式设置接入见下。

**正式设置与侧栏。** 先运行 `node scripts/build-framework.mts`，在同一 Vite 服务打开 `/prototypes/host5/theme/sidebar.html`。从左侧「界面设置」进入「材质」，试选「青灰」，观察右侧独立检查器；可取消试色、应用并保存、恢复默认。草稿与持久化仍归既有外观设置管理，Host 的可选主题能力只保留供消费者读取的运行时颜色。侧栏沿用原有布局、按钮和样式，只在启用组合主题时映射颜色。旧 Host 沿用原选色器。

`node prototypes/host5/theme/sidebar-check.mts` 检查同屏几何、两个区域的实际底色和强调色、取消前后的存储及重载恢复。旧能力形状由夹具模拟；传入 `HOST5_LEGACY_BUNDLE` 可替换为真实历史构建。Mac Chrome 157，1680×920，使用 `32fa6e7` 的 framework 源码构建旧 Host，搭配本次正式 UI 通过。独立无本体路径继续运行上节的 check.mts。#41 平板手感和本地 TTF 另行验收。

全目录严格类型检查可运行 `npx tsc -p prototypes/host5/tsconfig.json`。另有[特效定向检查](effects/README.md)及[侧栏定向检查](sidebar/README.md)。研究记录沿用 [#41](https://github.com/102326/DoL-Game-UI/issues/41) 和 [#42](https://github.com/102326/DoL-Game-UI/issues/42)。
