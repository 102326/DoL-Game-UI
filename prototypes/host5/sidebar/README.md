# Sidebar outer-layout experiment

`createSidebar(host, id, document)` starts disabled. `setEnabled(true)` registers a Host participant and claims `region:Host5Sidebar`; a persistent Host mount owns scoped CSS and the marker on a uniquely identified `#ui-bar`. `setEnabled(false)` or `dispose()` releases the claim and style. A direct body-child replacement bar is reacquired; missing or ambiguous shell and an already owned marker fall back to native. While enabled, observation is limited to body child changes and Host scene-ready notifications; while disabled this prototype has no participant, claim or observer. Nested shell changes are checked at scene-ready. No native element, focus target or listener is cloned, moved, clicked or re-rendered. This is an isolated prototype; no production boot path imports it.

Run `npx tsc -p prototypes/host5/tsconfig.json`, then `node prototypes/host5/sidebar/sidebar.test.mts <fixed-game-html> <published-rebuild-zip> <original-ce-zip>` from the repository root (Node 26, Python, local Playwright and installed Edge). The test checks all three file hashes and executes the actual rebuild CE script member in a neutral DOM with Macro, state and jQuery doubles. It invokes `CEstatebox` once and clicks its live button before, during and after takeover: the state changes once per click, and enabling/disabling does not rerender the macro or replace the focused button. It also checks the native test listener, scoped grid activation, duplicate participant and Host claim competition, bar replacement, scene-ready unsupported fallback and cleanup. A static substitution checks the original CE rule against the fixed passage. No game HTML is executed and neither CE integration is loaded by its real Loader.

For a visible neutral demo, run `npx vite --host 127.0.0.1` from the repository root and open `/prototypes/host5/sidebar/`. It contains only synthetic controls, including a simulated Mod button; it is not an acceptance view of the game.

## Source audit

Read-only fixed release HTML SHA-256 `9ecc02d91e481054bed564a4fe1975dd5c2e38edc051e9fac350ae5bebe282a5` (DoL 0.5.12.13 / Loader 2.101.1). SugarCube initializes `#ui-bar`, `#ui-bar-toggle`, `#ui-bar-body` and `#story-caption`. Its `uiBarUpdate()` calls `setPageElement("story-caption", "StoryCaption")`; the Engine invokes `UIBar.update()` when `Config.ui.updateStoryElements` applies. The authored passage contains `#storyCaptionContent`, `#overlayButtons`, button macros and an `overlayReplace` callback. The caption is therefore rendered output, not a stable reusable template: rerunning or copying it may repeat macro effects and lose listeners. The Host's existing SugarCube bridge uses `:passageinit` / `:onloadsave` for invalidation and `:passageend` / `:storyready` for readiness; this standalone experiment uses an owned DOM observer and does not itself emit or intercept those events.

Representative published Cheat Extended modernization `1.20.3.1-rebuild.30` ZIP SHA-256 `92db93acb221731334d72ef0922adf5c5f777550f621f09cc51b609236b91e89` (maintained fork, not the original author's package). Its boot rule targets `StoryCaption` and the exact `<<if $options.sidebarStats isnot "disabled">>` text, found once in this HTML. The `addon-replace/StoryCaption.txt` member SHA-256 `57e69c60cefdede44b13d0eeb1b049750685c0302474a500f1a64d92da7c76a6` contains that same condition and a newline; this particular rule alone must not be described as inserting CE UI. `scripts/CE_sideBarIcon.js` SHA-256 `857598d06c16d730969fd1ebb9c9cdbb1328e8413f1e13b87c65f5ec6e9f32fc` registers `CEstatebox`; its actual handler is the neutral test input described above. The package also contains a widget with an input calling `CEiconClicked()`. Static inspection does not establish that this widget is injected by that replacement rule.

The original author's CE `1.20.4` ZIP SHA-256 `980ba672661b0171923343dd03a242670fd3553208438355b5270e101ab8e134` uses the same single matching anchor, but its replacement member SHA-256 `ab96097398f8ef33970f008d4273adec0ca91eae2ddd1603fce2f2d72e4d071c` includes a conditional `CE_sideBarIcon` macro before the preserved original condition. The test applies this rule in memory and verifies exactly one inserted invocation; it does not claim Loader or macro execution for this original version.

No game HTML, ZIP, profile, save or device data is included. Real startup, CE macro injection, game layout geometry, native stowing and other Mods remain unvalidated. Grid styling changes presentation of direct `#overlayButtons` children; unknown children take a full row, but this is not a compatibility guarantee.
