# #41 · 天气在播时的面板反馈

**建议继续沿用现有默认策略。** 在这个轻量慢云场景中，预留名额确保了点击会播放淡入淡出，但没有使面板更早出现。若产品需要保留直接操作的视觉反馈，可继续研究按需名额；这份对照没有证明它能解决整机卡顿。

## 同条件对照

基于 `6db9f3b`，复用实际设置控制器、中性表单以及独立的 shadow DOM 检查器。A 是静态云层和共享名额；B 是慢云占用共享名额；C 保留 B 的天气层，同时在受信任按钮激活期间按需开放一个交互名额。由 Enter 激活的按钮按同一规则处理，脚本点击拿不到额外名额。C 的策略仅在实验页面生效。三个条件使用同一张自制 CSS 渐变云图。B/C 用同一条 8 秒线性位移动画，检测了连续播放及到端反向。

Mac arm64，Node 26.13.0，Chromium 153.0.8010.12，390 × 820 CSS px。以 ABC、BCA、CAB 顺序运行三组，每条件各 48 次实际浏览器输入，其中鼠标与 Enter 各 24 次。设置及独立检查器各执行开与关。输入目标节拍均为 300 ms。下表耗时以 ms 表示，双数值为中位数 / P95。

## 隔离与复跑

B/C 六个采样段内，天气均保持原方向与同一播放段。动画时钟与经过时间之差最大为 11.7 ms。每次操作后核对名额释放；独立面板播放时卸载、天气停止与重新启动、天气反向、Host 退出后计数归零均通过。两面板所在窄屏容器宽度相同且页面无横向溢出。真实 Android 触控、WebView 展示时刻和 Windows 均待实测。

在研究工作树根目录运行：

```sh
node_modules/.bin/vue-tsc -p prototypes/host5/panel-budget/weather/tsconfig.json
node prototypes/host5/panel-budget/weather/check.mts /tmp/host5-weather-result.json
node prototypes/host5/panel-budget/preview.mts
```

打开预览命令打印的地址，在其路径末尾添加 `weather/?mode=A`、`weather/?mode=B` 或 `weather/?mode=C`。[逐次输入、Event Timing 与帧间隔原始记录](mac-result.json)。
