# #41 · 在雨转雪途中加入

此前 provider 共享天气名称及粒子种子，每个 mount 在收到通知后自行启动 450 ms 插值。第二方在转场中点才接入，首帧仍从晴天起步。本次把转场参考时间与起始权重放在已有天气 provider 内；新挂载立即取样并绘制，之后两个独立绘制器使用浏览器同一帧的参考时间。基础色也从接入点继续向目标线性过渡。天气意图由现有消费者侧的调用方设置。没有引入额外全局帧循环。

## 中性浏览器实测

从 `f222cc6` 的两消费者天气原型接续。公司 Mac Chromium 153.0.8010.12，两个独立 SVG 各为 260 × 180，读回实际图元组的透明度与首个雨、雪粒子的坐标。雨和雪的材质常数分别为 .75 与 .85，记录将透明度除以对应常数得到混合权重。

| 时点 | A 的雨 / 雪 | B 的雨 / 雪 | 观察 |
|---|---|---|---|
| 转场 225 / 450 ms，B 刚挂载 | .50 / .50 | .50 / .50 | 首个雨粒坐标均为 (40.5, 128.25)，首个雪粒均为 (8.1, 16.875) |
| 315 ms，面板反馈已经反向 | .30 / .70 | .30 / .70 | B 释放重挂后仍与 A 相同，A 保留同一个 SVG |
| 中途改回雨，再过 225 ms | .65 / .35 | .65 / .35 | 改目标当帧仍为 .30 / .70 |

同种子、同尺寸、只通知“雪”并另起时间线的负对照，在中点挂载时雪权重为零。另用浏览器自然帧时间、无固定时刻注入复测，两边首帧雪权重相同（本次约 .4813），坐标也相同。两方持有各自的 DOM 和绘制回调，测试没有复用同一张渲染图。面板反向检查位于独立的前景轨道；本轮没有触及 Acrylic 的祖先。

B 先退出、或 B 重挂后 A 再退出，粒子场租约均剩 1；最后一方退出变为 0，再申请得到新的粒子场。provider 主动销毁后剩余 Host claim 为零。这里验证了引用与挂载释放，未测 GPU 内存。
