## 战斗原生选择器

采用原生 Select CSS 增强，没有新增代理控件、第二份值状态或事件转发。支持引擎通过 `appearance: base-select` 与 `::picker(select)` 定制浏览器原生弹层；不支持时保留系统选择器。这一能力的来源见 [Chromium 文档](https://developer.chrome.com/blog/a-customizable-select)。

范围仅为已检查的 `.dcu-shell #mouthaction select#listbox-askaction`。未知第三方 Select 不接管。同类官方选择栏的推广已有授权，但须先确认节点合同和交互，不用全局选择器一键覆盖。

挤压来自原生 label／内部容器与主题行内布局的组合：仅设置百分比最小宽度无法为内容提供稳定宽度。最终规则使用 `inline-flex`、`12rem` 宽度与 `max-width:100%`，文本与箭头分开排列。Android 现场修正后闭合控件为 192 × 45.6 CSS px，不再把箭头挤到下一行。

`combat-select.cjs` 使用实际模块与代表性原生父子结构，检查原节点身份、一次选择一次原生 input／change、重选当前项不重复发事件、禁用选项／选项组、键盘、Escape、外部关闭、快速开关、动态选项、窄屏滚动、减少动态效果、原 Continue 夹具回调与 Passage 离开清理。

Android 17／WebView 154 的独立测试 App 中，只对已安装 3.0.0 注入局部候选 CSS：两次 CDP 合成触控选择产生各两次原生 input／change，恢复原选择，原 Select 和 Continue 节点身份保留，回合数未变化。未点击真实 Continue；具体游戏业务变量未取得有效值，不以控件值替代该变量验收。这不是物理触控，也不是候选 ZIP 安装证明。

## 存档窗口视口

针对 2.x 用户报告，先检查当前 3.0.0 的真实 Android 组合：100% 字号、1363 × 876 CSS px、原版优化的原生卡片视图能滚到末尾控件，未执行存读档。该组合不等于无 Adapter 的全部模式，也不等于真实 iPad。

受控夹具在 844 × 390 复现同类裁切：原生网格轨道被内容撑高，百分比最大高度随之扩大，窗口底部和操作区超出视口。修复仅在自有存档根节点存在时约束窗口至 `100dvh - 24px`，内容区采用 `min-height:0` 和滚动，不改变保存业务。

`saves-viewport.cjs` 在 2560 × 1440、2048 × 1152、1363 × 876、1024 × 768、768 × 1024、844 × 390 的两种模式中，以 100% 设置检查末尾原生控件可见且可命中，并检查偏好在夹具重新加载后保留。没有派发保存或加载操作。真实 iPad Safari 和新包下整 App 重启仍未验证，不能把这组结果写成历史 iPad 问题的全部根因已解决。

## 失败记录与交付边界

- 初次局部 CSS 在收缩的父容器内仍只有约 66px 宽；实际画面未通过，随后修正为明确宽度并重新核对。
- 浏览器夹具中 Playwright 的 disabled 辅助判断对嵌套在 radio label 中的原生 option 返回异常；保留失败记录，改用原生 `:disabled` 与实际点击／事件计数验证，没有移除禁用行为断言。
- 存档横屏夹具先失败，再修复布局；保留裁切记录，不用缩小字号避开缺陷。
- 设备证据、错误日志与候选身份保存在忽略目录 `tests/artifacts/kraft-work-maintenance-20261019/`，不提交游戏画面、私人数据或第三方包。自动 CI 只上传仓库自有受控用例日志。

本地 UI 技术版本暂保持 3.0.0，候选字节已不同于公开冻结包，不能直接替换公开同名附件。Host 公共协议和运行代码未修改；CI 重打包所得 Host ZIP 也不替代已冻结公开 Host。下一次运行版本号、真实 Loader 整包验收与发布须另行决定。
