# 原版优化衣柜兼容 1.0.1

2026-10-20，关联 [Issue #13](https://github.com/102326/DoL-Game-UI/issues/13)。独立包技术名仍为 `DolOptimizationSoftWet`，主 UI 为已发布的 3.0.2，不修改其运行包或 Host 公共合同。

## 对应目标版本

开发前已从作者仓库核对最新正式版 [v1.1.2](https://github.com/ANLINSTUDIO/Degrees-of-Lewdity-DolOptimization/releases/tag/v1.1.2)，发布于 2026-10-19；Tag 指向 `0bfba4bfb719dbf35ed66f4875cefe394ff0fa61`。作者附件 `Dol-Optimization-v1.1.2.mod.zip` 的 SHA-256 为 `12e6f38a0d5c77478e88b01904b2aa116cd7d33361782dd537d02793b92dd2d8`，已下载核对。

v1.1.2 默认关闭叠加服装。兼容包显示原未启用提示，用户仍在原版优化设置中决定是否开启。不能把该默认变化统一认定为 UI 不兼容。

固定 1.1.1.5 回归输入来自此前已授权测试组合，导出 ZIP SHA-256 为 `94644b19e199bdb0abd3f8e7b35dd95de2cecba239c882ee9f2e194d8849367a`，不冒充作者原始发行 ZIP。其管理模板与 v1.1.2 字节相同；穿戴补丁仍逐版本使用各自原包。

## 实现范围

1.0.0 只声明存档页适配。现有主 UI 已使用原 `wearlink_norefresh` 穿戴入口，缺少的是新衣柜内的叠加装备管理区。

1.0.1 从 ModLoader `getPassageData('Widgets Wardrobe')` 的已补丁内容读取已知管理片段，按原当前部位与 `selectWardrobe()` 上下文渲染。原模板生成的链接继续执行原版优化的卸下、换层及主装备交换，再调用原 `updatewardrobe`；兼容包只刷新主 UI 展示，不复制规则、不直接写叠穿数组、不注入第三方源码。

管理区使用 3.X 黑灰材质和至少 44px 链接命中范围。已有原存档描述、分页和槽位适配保留。主 UI、Host、其它兼容包不在此次附件替换范围。

执行前复核当前 Passage、变量对象、部位、库存对象与状态摘要。旧按钮、重复点击和上下文变化被拦截，不自动重试。管理模板、版本或方法无法确认时退让；UI 忙碌、关闭、Passage 离开和兼容包销毁均清理自有区。保留“原版及扩展信息”入口。

最终窄屏画面在原欢迎界面正确关闭、原生侧栏收起后检查。早期截图因测试直接关闭欢迎弹窗而残留上游 `gateBlur`，不作为视觉验收依据；后续使用原欢迎按钮完成准备，并检查所有祖先无 filter 模糊。原始失败记录与后续清晰结果留在本地。

`ci:check`、八包构建、七项包合同反例及两次构建一致性通过。旧版本 CI 输出文件曾被“禁止混入额外制品”检查拒绝，定向移至本地证据目录后重新运行，未放宽检查。

首次真实 Loader 检查表明普通 SugarCube Story 查询不保留该 Widget 源码；改用 Loader 公开段落读取接口后通过。旧存档测试夹具缺少目标日志接口和 3.X 标记，按实际宿主补齐，不删除原断言。Windows 本机 CI 证据测试的符号链接创建因系统权限失败，保留记录，不改权限或断言；云端检查另行核对。

本轮未验证 Android／iOS、物理触控、全部服装套装／扩展槽位、长期资源或所有 Mod 组合。最低依赖仍是范围声明，模板与能力合同同时约束是否启用，不承诺任意未来版本自动兼容。测试不操作私人存档、账号或云端。

## 安装与发行

使用原版优化时，停用同技术名的 1.0.0，导入 `DolOptimizationSoftWet-Optimization-1.1.1.2-plus-v1.0.1.mod.zip`，排在原版优化和 UI 后并重启；不要同时启用两个版本。未知问题可恢复保留的 1.0.0，或停用兼容包后使用原版及扩展信息。不要清空游戏数据。

负责人授权通过验证后将新包及校验清单更新至现有 v3.0.2 Assets，不创建新主 UI 版本或重写旧 Tag。源码与包摘要另存维护记录；最初 3.0.2 Tag 下的身份文件仍代表首次发行快照，不用于冒充这次兼容包的新摘要。
