# Stone Free NO.1 首轮开发记录

原型版本：3.0.0-stone-free.1。分支：development/stone-free-3.0。日期：2026-10-12。

## 玩家可见行为

单击球体打开扇形，单击再次收起。“全部工具”进入网格；两种模式使用同一份settings/inspector/move定义和执行入口。界面设置和只读Runtime Inspector是实际现有UI功能，不是静态样例。暂不可用的工具给出原因；没有代理剧情、购买、穿戴或存档业务。

长按450ms进入拖动，提前移动超过8px取消点击和未激活的长按。拖动后松手保存位置，不误开菜单；pointercancel/lost capture或窗口变化取消当前拖动并恢复原意图。只对球体捕获Pointer，不接管整页手势。移动面板的水平/垂直滑块可用键盘调整。位置不强制吸边。

位置按可用窗口的归一化坐标保存，visualViewport与安全区影响当前实际位置。窗口收缩、旋转、缩高不会覆盖保存意图；已识别战斗底栏与球体重叠时临时让位。菜单优先向上或下展开，空间不足临时用网格，不改变保存的默认模式或球体位置。菜单工具按压期间冻结几何更新，松手后才恢复计算。

设置中的独立小节提供默认模式、扇形工具选择、关闭、找回与重置位置。扇形可选少量工具，网格显示所有三个工具；没做多级分组、搜索、任意脚本、自定义第三方命令或完整设置中心重排。

## 接入与所有权

新代码在src/floating，保存键DoLGameUI.stoneFree.floating.v1独立于2.6缩放偏好。值是已验证的布尔项、模式、0–1坐标及工具ID，未知ID丢弃，不保存DOM/闭包/脚本。root.DoLFloatingTools只是原型内部入口，不扩大公共UI API v1契约。

main增加启动和销毁；runtime/master只新增总开关通知事件；SettingsPanel加一个独立小节。原型不重建Surface系统，球体宿主从不调用showModal。只有具体设置/Inspector工具沿用原有Modal业务。

宿主pointer-events:none，只有球体和可见菜单控件接收事件。菜单外点击监听只在展开时存在，不preventDefault或stopPropagation外部事件。没有全局keydown/pointermove/pointerup拖动监听。关闭/隐藏会清理Vue宿主、临时菜单监听、resize/visualViewport监听、ResizeObserver、长按timer和pointer capture；核心destroy额外清理master通知与恢复观察、帧回调。总开关关闭后仅保留一条内部状态通知用于再次启用，不保留输入拦截。

遇到可见原生dialog、#customOverlay、#ui-dialog时临时卸载球体，保留仅用于恢复的只读观察。不开关、不搬移、不复制对方节点。自有宿主ID被他人占用时不删除对方，不创建第二个同名宿主。

## 验证

复用已有Playwright、固定SugarCube夹具和构建流水线，未建ModLoader/SugarCube模拟器或自动化平台。实际环境macOS ARM、Node24.18.0、Python3.12.14、Chrome155.0.8059.40、Playwright1.63.0。临时NODE_OPTIONS将既有Edge启动改为本机Chrome。

新增检查：floating-preferences.test.cjs（默认/坏配置、稳定ID、位置意图和临时投影）与floating-tools.test.cjs（真实点击/长按/取消/原功能/窗口/Passage/清理），另有floating-boundaries.test.cjs覆盖独立审查的三项回归及暂不可用工具说明。已证明RC1旧构建因没有球体而失败；原型完整交互检查通过。新增检查加入已有unit和layout/release分组。

已验证：点击展开/收起、空白点击、Escape、自有设置/Inspector真实打开；扇形→网格、移动滑块；长按拖动不误触、提前移动取消、pointercancel回滚；六种窗口320×568、844×390、768×1024、1024×768、390×320、1200×900及返回原窗口；保存意图未被窗口覆写；Passage往返单一球体；第三方原生dialog节点不变并退让恢复；隐藏/设置找回/关闭/总开关重启/核心销毁/重复注入。关闭后原原生按钮可点击、正文可选择；工具操作阶段原节点/父级/游戏变量保持。截图已查看。

初始失败保留：类型推断修正；基线红测缺CSS资源先修夹具再确认“球体不存在”失败；监听计数改为相对既有原游戏监听；外部正文定位改为唯一训练场标题；核心销毁会同时移除原有Core监听，因此最终计数应为0；幂等销毁检查保留API引用避免删除全局后误读变量。这些没有削弱功能断言。

独立审查发现并修复三项P2：临时网格未补齐工具、菜单外部释放后位置锁残留、隐藏期间阻挡状态过期。前两项在修复前由新增回归直接失败复现；第三项独立审查复现，回归强化为显式show同步恢复，不依赖其他DOM变化。菜单使用自身控件的Pointer capture及作用域click保护，外部释放不执行工具，取消/失去捕获/失焦会解锁。另修同类不可用工具的临时网格分支，保证工具说明可见且网格仍完整；设置工具检查真实设置接口是否存在。组合检查包含11个unit脚本及既有layout/combat分组；原生master-native状态比较曾失败，最终精确差异为clothesiconFile临时绘图路径。原版clothing-v2.twee使用timed/repeat在后台生成其它商品页，clothingicon会写该临时变量；原测试只等首件商品就拍快照。补等原版所有页生成结束后，保留完整状态、默认筛选和节点不变断言，无产品业务修改。失败、诊断与补测日志保留。补验重启后设置小节正确反映保存的展开模式。11项单元脚本与16项layout/combat浏览器检查分段通过；不表述为一次组合全绿。最终构建、回归和提交的精确身份见交付清单。不能据桌面证明宣布T0正式发布通过。

## 尚未验证与已知边界

Android/WebView真实触控、长按平台取消、多点、系统返回、软键盘/visualViewport实际更新、安全区、缩放手势、分屏/小窗均为Not Validated。矮窗口只是布局检查。未知第三方自定义浮层未必能自动识别；原型以较低层级退让已知层，玩家可以随时隐藏/关闭。没有任意Mod兼容保证。

visualViewport和env安全区已留实际计算，但本机零安全区不是设备证明。极窄/极矮到无法容纳52px球体和边距的窗口不属于本轮支持证明。扇形当前仅上下方向，空间不足临时网格；更精细左右方向与触控手感需实机后迭代。没有声明GPU、功耗或长期性能改善。

## 三个结论

A：原型可实际操作，不是静态外观。B：上述桌面交互已验证，Android清单未验证。C：可以在正式2.6基线继续集成；代码独立，接入点只有入口、销毁、总开关通知与设置小节，无需大规模重写。但必须先合入/变基2.6的新缩放合同及其验收，不能把当前旧合同作为3.0正式基础。
