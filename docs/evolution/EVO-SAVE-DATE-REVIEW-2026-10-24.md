# Evolution：存档附加日期异常专项归因

2026-10-24。接收负责人补充与小鸥专项复核后，先核对现有测试档，没有重新保存或修正时间字段。本文记录实际归因，不是已安装修复或发布批准。

## 结论

本次 `(1/1/NaN aN:aN undefined)` 的直接生成点已定位到**原版优化 1.1.2.1 的附加游戏日期显示链**：它把 `saveItem.data.delta[0].variables` 当成当前有效状态读取，而当前测试档含四帧 SugarCube 历史，活动索引为 3；首帧 `timeStamp` 是 `undefined`。

`startDate + undefined` 得到 `NaN`，原方法格式化结果与现场异常逐字一致。用实际宿主的 `State.deltaDecode` 解码历史、取活动帧后，两个时间字段均为有限数值，得到 `(2022/9/4 07:00 星期日)`，与已载入的 `Time` 以及 UI metadata 中的 `2022/9/4 07:00` 一致。

关闭 Soft & Wet 的存档展示及对应外观适配，再经原入口重新打开页面，异常仍存在。因此，本例不是 Soft & Wet 自有日期快照生成了这串错误；它显示的是目标 Mod 附加的 `.datestamp > .pink` 节点。该证据不等于所有存档字段均正确，也不保证其它日期异常具有相同原因。

## 现有异常与必要字段

只读取本轮新建测试槽 4 的必要投影，没有输出完整存档或其它槽剧情内容。

| 项目 | 现场值与含义 |
| --- | --- |
| 现实保存时间 | `2026/10/24 00:43:53`，详情时间戳为有限数值 |
| 异常部分 | 原生 `.datestamp` 内的 `.pink`：`(1/1/NaN aN:aN undefined)` |
| 实际可见节点 | 当前“最近存档”行 `#latestSaveRow.savesListRow`，其保存槽指向 4；不是自有 gameTime 文本节点 |
| 历史表示 | `data.delta.length=4`，`data.index=3`；后续项是增量，不是每项独立完整状态 |
| 原始首帧 | `startDate=63797871600`，`timeStamp` 属性存在但值为 `undefined`；不是 JSON 中的 null |
| 解码活动帧 | `startDate=63797871600`，`timeStamp=0`，均为有限 number |
| 实际 `Time` | 2022/9/4 07:00，年、月、日、时、分均为有限 number |
| UI gameTime 快照 | 字符串 `2022/9/4 07:00` |

`idb.getItem(4)` 的当前实际实现使用 IndexedDB readonly transaction，返回持久化历史表示；没有自动把历史首帧转换为活动状态。`State.deltaDecode` 的宿主实现为克隆首帧并依次 `Diff.patch`，本次只作只读副本计算，没有 unmarshal、load 或写回当前 State。

## 最小隔离与完整性

1. 保留原 UI 状态打开存档页：适配 full match，可见 `.pink` 显示原异常。
2. 关闭页面，仅通过已有公共偏好暂时停用自有存档展示，再重新打开原生存档页。此时 `.dgs-host=0`、外观适配 match=none；相同槽位的原生附加日期仍异常。
3. 关闭页面，恢复原偏好与原 localStorage 表示。Bedroom、回合、资金均未改变，原版优化设置摘要也未改变。
4. 比较测试槽原始存档及详情 metadata 的前后 SHA-256，分别相同。没有调用保存、载入、删除、导入或导出，也没有改写原槽 1–3。

这里只停用了存档展示和对应适配，没有卸载整个 UI/Host 或关闭原版优化。不把本次结果扩大为“完整无 UI 组合验证”；源代码、实际字段和全新原生页面仍足以定位本例的错误取值。

## 测试结论与修复边界

本次专项断言使用真实 WebView 的 `DateTime`、`getTimeString` 和现有异常结构，正常活动帧与异常首帧均被验证，没有把日期构造器替换成固定正常值。现场证据摘要见[数值与身份记录](EVO-SAVE-DATE-REVIEW-2026-10-24.json)。

小鸥指出的 CI 覆盖局限仍成立：旧 `optimization-adapter.cjs` 提取旧 async initsave 签名、模拟正常 DateTime，不能证明 1.1.2.1 的日期语义；通用绿灯也不是日期语义验收。本次没有把方法提取失败当业务反例，没有更改或放松 CI，没有把本地诊断断言冒充新的必需门禁。

**尚未安装任何生产修复。** 建议把这条最小复现交给原版优化作者：依实际存档表示解码历史、读取 `data.index` 对应活动状态，并检查时间字段类型/有限性；不能简单改成读最后一个原始 delta，也不能用当前游戏时间冒充每个存档的时间。其自定义描述时间戳也读取首帧，属于同一源码线索，但本轮没有执行描述写入，不宣称该功能已证实损坏。

若需要临时兼容，应只处理明确的附加日期显示边界，保持原生保存/读取/删除和存档格式不变。需先确定采用上游修复还是自有显示兼容，再针对实际修改补正常/异常及相应表示回归；本次没有擅自补丁目标 Mod 或隐藏异常文字。
