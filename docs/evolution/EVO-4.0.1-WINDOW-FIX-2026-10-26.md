# Evolution 4.0.1：窗口、悬浮工具与商店回归

日期：2026-10-26。基线为已发布 v4.0.0（f7f81c6），从 main / 4b62b96 开始。关联 Issue #28、#29。本文件记录本轮技术范围；4.0.1 公开前仍须最终准确源码 CI、制品与装机核对。

## 修改范围

- 负责人明确要求与设置页同步开窗：官方侧栏和已识别兼容窗口现在共用 `fadeWindow` 的 100ms linear 打开、80ms 背景退场。删除旧 420/240ms 材料展开及重复导航／正文淡入；原生关闭动作仍即时执行，不包裹或延迟原事件。
- 原生已核对入口在首帧前启动短过渡；迟到的 Adapter 识别接管现有动画，不把已经显示的窗口再次淡入。新增“先淡入、后识别”的真实路径断言。同一可见窗口在兼容器 partial/full 重新识别或装饰元数据更新时不重新入场。真实关闭后再次打开仍正常演出，关闭中反向保持背景与焦点。
- 兼容识别接管提前启动的过渡时，同步保留关闭后的焦点返回目标。新增 Hub／原生侧栏两种来源检查；修正前能准确复现焦点未返回，修正后通过。不重新播放动画，也不改变原事件。
- 旧材料层及 100px 校准盒整体退出运行，不再为其强迫布局；导航元数据只在变化时写入。设置原有 100/80ms 参数不变。
- 非设置窗口的旧天气保持原模型、雨量、速度及颜色，绘制集中到完整标题／分类区并向下渐隐。根据实际区域尺寸更新，避免每次导航刷新同步重测；设置已认可的模型保持。
- 明确选择扇形时，五个官方工具按弧线排布；空间不足才退回网格。关闭阶段结束后，隐藏菜单和详情表面不参与绘制。
- 商店分页构建移除会进入 Widget 的行注释，保留原生和实验两条回调。实际 Widget 会折叠空白，生成的 `//` 曾吞掉代码并触发 `Unexpected end of input`，不是 TypeScript 类型导致。

## 性能：已确认与 Unknown

旧源码确实叠加 CSS 与 WAAPI 入场；新代码取消了重复路径，但这不等于所有开窗耗时已解决。ModHub 基线只记录到一次主 UI 的新开窗调用，不能写成“两次 WAAPI”。

同场景交错 master-on/off 对照中，停用 UI 后仍有约 208–217ms 的 ModHub rAF 长间隔；保留 UI 的两次样本为 167/375ms。画面不同，不能将差值全部归给某个特效。不能因此认定是 DoL 原版，可能还有其它 Mod、WebView 或设备调度。V8 采样中的 ModHub `inferRequiredDependencies` 是上游计算热点，不擅自删校验或改业务。

装饰层改放前景、临时关闭 root 模糊都没有稳定收益，已撤回，没有把它们写成优化。临时天气隐藏仅用于定位，不能作为产品效果退化。rAF/CPU 采样不是实际呈现 FPS；没有新增完整系统 trace、长期无泄漏或最小 Mod 归因结论。

4.0.0 的原速素材与历史测试按未变范围复用；它们不替代新源码／新 ZIP 的验证。
