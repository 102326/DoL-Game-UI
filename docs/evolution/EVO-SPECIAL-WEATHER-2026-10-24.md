# 特殊天气与环境响应补充

2026-10-24。负责人在日期修复期间新增授权：接入血月，并检查其它原生特殊天气效果。本次仅补充现有窗口环境层，没有修改游戏天气生成、时间、剧情、属性或存档规则。

## 识别与效果

当前测试 App 的 DoL 0.5.12.13 原生天气共有晴、薄云、厚云、小雨雪、大雨雪、风暴、雷暴七种生成类型；降水形态由温度决定，雾量另行提供。

| 原生状态 | 本轮处理 |
| --- | --- |
| `Weather.bloodMoon === true` | 暗红月体、局部红色月晕与缓慢云影；保留同时发生的雨雪与雨量 |
| 原生 `location === 'tentworld'` 的紫色天空 | 紫色环境辉光与暗影漂移，不绘制触手或改剧情 |
| `Weather.Temperature.isExtreme()` 且温度大于 30°C | 局部暖色热浪光感；普通暖天气不误触发 |
| 同一原生极端判定且温度不高于 -18°C | 冷色边光与静冷云影；不凭空制造降雪 |
| 节日强制大雪 | 游戏本身映射到降雪，复用已有霜羽/边霜与雪粒，不复制节日日期规则 |
| 暴风雪、雷暴、雾 | 保留现有降水、雷光及雾处理；特殊环境色与降水分开，互不替代 |

血月优先于温度氛围；异世界场景使用它自己的紫色天空。只读取原生状态，不按设备日期推算血月，不读取本地世界腐化值来猜天气。体温、室温、水温、世界腐化贴图不是本轮新增天气类别；未知第三方气候不自行识别为已支持。

负责人提供的 [Wiki 血月页](https://degreesoflewditycn.miraheze.org/wiki/%E8%A1%80%E6%9C%88)被站点验证拦截，本次未据其内容作结论。触发依据来自实际 App 的 `Weather.bloodMoon` getter、原生天气生成表和该 App 未改 HTML 中的天气/温度/提示源码。未复制或重新实现原游戏的月末与日出日落计算。

## 实现与验证

原生窗口使用现有天气装饰节点；设置沿用同一 Canvas 和资源 owner，添加氛围绘制并复用现有控件/正文保护区域。没有新增独立动画循环或计时器。关闭、隐藏、减弱动态及 UI 动画关闭沿用原生命周期。

- 类型、Framework 构建、原顶栏天气合同、资源合同及新增 `weather-special.cjs` 通过。专项覆盖严格布尔血月、紫色天空优先级、温度边界/原生极端判定、异常 getter 退让、雨雪共存、实际正文段落和关闭按钮像素、真实控件、390px 窄屏及释放。新增专项纳入标准 CI 与 Expected Lock。
- 专项最初比较整张圆角预览卡时，发现右下边缘一个像素的 RGB 相差 1；保留失败材料，定位为合成边缘，改用实际正文段落作为本专项的阅读像素对象。未删减原 W01 的整卡像素断言，也未用该差异宣称正文遮挡。
- 本机 W01 的 3500ms 雨量过渡检查超时，分别以改动前 `2ef3d68` 的三个天气模块与当前模块作同条件对照，二者均超时，后续快照均已收敛。未改时限或断言，未冒称本机完整 W01 通过；新增失败即时快照，完整检查另以当前源码 CI 结果记录。
- 新 UI 候选持久安装到 M367FC / Android 17 / WebView 155，重启后全部 ZIP 成员、Loader 顺序和禁用列表核对一致；兼容包仍为日期修复版 1.0.3。
- Android 以临时只读天气绑定验证血月/热浪/严寒绘制：保留当时实际 storm 降水，单一 Canvas、装饰不接收输入、真实关闭命中与释放均通过。最后恢复原 Weather 属性描述符；游戏状态、位置、偏好未变。未强制推进时间或改写存档。
