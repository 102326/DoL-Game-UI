# TS First：发布顺序与迁移范围评估

2026-10-24。源码基准 `ff7942dc78fed54b5451d7cdcdf6c454a83caf01`，分支 `dev/evolution-4.0`，UI仍为 **4.0.0-rc.2**。负责人已暂停此前正式发布执行，要求先评估、确认后再迁移。本轮没有迁移源码、调整正式版本、合入main、创建Tag或发布。

## 建议结论

**建议把TS First前移到4.0发布之前，采用“当前交付链先完整约束”的有界方案。** 重点是把仍在工作的JS工具和测试变为受检查的TS，同时补上已有TS的数据边界；不需要重写已认可的UI、Host或动效架构。

这对应负责人列出的第二种方案。建议范围是125个独立JS文件、一个离线HTML工具的逻辑、商店Twee的自有回调，以及下文已有TS的约束缺口。其余118个未进入本次标准/研究静态闭包的测试文件和11个预览HTML，也列入后续迁移清单，不能把它们一律称为“必须JS”或直接当成废弃文件。

关于CommonJS保留、CTS/MTS路线、导出类型、最低Node和冷启动影响，见[CTS专项补充](EVO-TS-FIRST-CTS-2026-10-24.md)。需要CommonJS不等于源码必须保留JS。

这个范围完成后只能称“4.0交付链TS First完成”，不能声称“全仓所有自有代码已迁移”。如果负责人希望4.0前完成全部仍维护的自有JS，第一种方案也成立，但应接受更大的测试迁移工作量。两种方案都排除上游生成模型和已封存展示。

## 一、真实盘点

数据来自Git跟踪文件、TypeScript AST、Vue SFC解析、实际构建入口、标准/研究Catalog和依赖读取；不统计node_modules、本地dist、私人测试材料和下载制品。逐文件建议见[清单](EVO-TS-FIRST-INVENTORY-2026-10-24.json)。非空行仅是物理规模，不是工作量：不少文件一行就包含一整段浏览器夹具。

| 部分 | 已有TS | 剩余JS与处理 |
| --- | --- | --- |
| 产品Core `src/` | 70个TS、19个Vue；Vue脚本均为TS | 没有独立的自有运行JS文件；另有一个6651非空行的上游衍生/生成模型，不能误算成待重写的自有模块 |
| Host与公共合同 | boot、host、signals、contracts共4个TS | 不是待转JS；应核对宿主桥接与投影的真实数据边界 |
| 正式UI、Hub | 9个TS、1个Vue | 没有独立JS；球体、天气、生命周期等不需要为迁移再次重写 |
| Framework其它组件/样例 | 17个TS、10个Vue | 另有6行的Factory Vite配置MJS，可转TS；不把这些样例全部算作玩家运行模块 |
| 兼容包 | 8个TS入口，505非空行；当前发行集合为7包，另有未进入九包集合的Lyra衣柜入口 | 运行逻辑已经TS；ReOverfits还有1个15行CJS检查脚本，应纳入测试迁移 |
| 测试 | 1个公开类型测试TS、1个历史Vue夹具 | 203个CJS，11047非空行；另有4行浏览器JS夹具。大部分迁移量在这里 |
| 构建、CI、录制等脚本 | `scripts/ci/`12个TS；其外6个TS | 29个CJS＋8个MJS，共37个、1605非空行；其中1个CJS已只是2行TS桥，不能算成一整块未迁移实现 |
| 组件实验室 | 1个TS、1个TS Vue | 1个26行CJS索引器可迁移 |
| 根配置/早期入口/示例 | 7个TS，包括早期注入脚本及5个Vite配置 | TS后缀不等于已进入检查；见下一节 |

全树共有245个独立JS/CJS/MJS文件：1个上游生成模型，244个自有文件。扣除纯浏览器JS夹具，并将CJS薄桥纳入可有TS来源的迁移项，**独立文件迁移候选为243个**，而不是“产品还有数千行JS未重写”。全树35个Vue文件的脚本均是TS，包括研究、实验室和历史夹具；正式Core/Framework部分为30个。

### 后缀之外的JS

- `twee/`四个补丁包含SugarCube表达式和JS；其中两个文件含8处`<<run>>`，其它还有`<<set>>`等协议表达式。`patch-resize.twee`的实验分支仍有自有resize回调，是运行逻辑，应考虑移到已存在的 `shop-page-experiment.ts`，Twee只保留调用。上游else回退、宏执行时序和四项替换合同必须保留，不借迁移改业务。
- 12个非归档HTML包含内联JS：`tools/device-probe.html`44非空行，另11个天气预览页主要是播放/审阅控制。前者建议本批抽成受检查的TS，再生成可直接离线打开的HTML；后11页进入后续迁移。HTML要直接打开不等于其自有逻辑必须用JS写。
- `docs/EYES_*.html`中的5个带JS旧展示页属于已封存设计，不恢复维护、不为了统计重写。CSS、原生Twee模板和测试中的恶意/历史JS字串也不是普通TS模块。
- 最终ZIP的 `index.js`、适配器JS和early脚本是Loader要求的生成输出；继续输出JS，不反向要求Loader加载TS。

## 二、已有TS是否有效

**已经有效，但检查范围和边界约束还不完整。** 本轮在未改源码上实际执行 `npm run ci:check`，类型与Framework检查通过；这不是迁移后的新验收。

| 检查 | 当前情况 |
| --- | --- |
| 产品与Vue | 根配置检查 `src/**/*.ts/vue/js`；Framework配置检查Framework TS/Vue |
| 兼容与早期入口 | 独立适配器配置、公开消费类型测试和early入口检查已接入typecheck |
| CI | `tsconfig.ci.json`严格检查12个CI TS模块；研究入口另有原型/天气配置 |
| 严格程度 | `strict:true`，包含隐式any/空值/函数等严格规则；`skipLibCheck:true`，`noUncheckedIndexedAccess`和`exactOptionalPropertyTypes`未启用 |
| JS | 根配置 `allowJs:true`，但没有 `checkJs:true`。这允许上游模型被引入，不等于其内部受严格检查；工具和测试CJS也不在这套检查范围 |
| 漏检TS | `scripts/`根部6个TS工具及根部5个Vite配置未作为现有类型检查入口覆盖。Node运行时擦除类型、Vite成功转译都不代替类型检查 |

AST扫描正式产品/Framework、兼容入口和12个CI TS模块：没有显式any或 `@ts-ignore/@ts-nocheck`，但有183处类型断言和142处非空断言。这里包含合法的`as const`和受生命周期约束的DOM引用，不能据数量宣布183/142个Bug。另有3处显式any在实验室/原型：`component-lab/App.vue`及两个Hub演示Vue。公开类型测试的4个 `@ts-expect-error`用于证明错误合同会被拒绝，应保留。

### 编译器实测发现的边界

| 位置 | 当前实测/源码事实 | 建议 |
| --- | --- | --- |
| `scripts/ci/runner.ts:15`、`research-runner.ts:15` | `require('../ci-evidence.cjs')`得到的e被编译器推断为any；研究r同样如此。TS本体里的参数/结果约束可被这一侧穿透 | 迁移evidence、Catalog、研究编排等实现，并使用有类型的导入/导出，不能只给require结果强制套接口 |
| `src/saves/metadata.ts:28–35` | `JSON.parse`导致detailsFor实际推断为 `Promise<any>`；之后把unknown断言为IndexedDetails[]/LegacyDetails，仅做顶层数组/对象判断 | 从unknown开始，校验实际使用的槽号、记录与metadata投影；内部只传已验证结构，不深度遍历所有存档 |
| `src/wardrobe/render.ts:53` | 上游JS模型返回值被断言为PrivateModel/options | 保留上游算法与许可；为自有边界建立准确的输入/返回投影，必要时校验有限尺寸、compile函数和层数组 |
| 衣柜/战斗Vue挂载 | 存在 `as unknown as WardrobeView`及手写暴露结构 | 尽量从真实组件实例/显式expose推导类型，处理nullable ref；不能靠复制一份声明掩盖组件不匹配 |
| `src/wardrobe/host.ts`与各Adapter的Window声明 | 描述期望的外部形状，不能证明实际游戏/Mod返回值满足；ClothingSlots的字符串索引也不能保证该槽实际存在 | 在进入自有数据模型的少数边界缩窄、检查实际需要的字段；不为整个第三方世界编造全量类型 |

本轮把CI配置临时加上 `noUncheckedIndexedAccess`与 `exactOptionalPropertyTypes`运行了一次，只读探针得到5条诊断，配置没有修改。它们可作为CI迁移批次的明确收紧任务，不应一口气打开所有额外选项后用断言压平错误。产品侧是否全局开启这两项，应在边界批次按实际诊断决定；`strict:true`不能下降。

## 三、能解决什么，不能解决什么

能解决：跨模块参数/返回结构错配、Vue暴露字段漂移、资源句柄与可空引用误用、CI结果结构与状态联合不一致、脚本路径/目录/包身份模型在调用链中的误传。前提是实际代码进入检查，而且调用方没有通过any或无依据断言绕开。

不能承诺：转TS后雨效更快、不会闪烁、不会发生竞态、日期永远正确或第三方绝不返回异常。类型在运行时被擦除，`NaN`与`Infinity`本身仍是number；`number`也没有表达时间单位、可用日期、业务范围和当前场景身份。

本轮用原 `createSaveMetadata`模块和纯合成数据做隔离探针：有效槽记录可读；返回 `[null]`时顶层数组检查通过，后续d.slot触发TypeError。这证明已有TS边界缺少结构缩窄，**不是负责人反馈日期异常的复现或归因**，没有接触真实存档。若修复此项，应作为有反例的独立行为修复提交，不混入只改语言的提交。

已有正确防线应保留：Host投影拒绝非有限数、限制深度和容量；状态服务检查Number.isFinite；购买确认检查金额/数量并在未知结果时退让；原版优化日期兼容包已检查存档来源、有限时间、日期字段和最终格式。日期兼容补丁本身已经TS，不能把历史异常归罪于“JS没转”。

需要校验的入口为：存档/本地偏好与别名JSON；Loader/Host/Mod返回的必要能力和数据；JS模型与Vue挂载接口；金额、日期、天气和布局的有限值/范围；CI文件、子进程结果、路径、来源身份和证据摘要。复用现有guard，只在读入或数据变化时检查小投影，不在每帧深扫整个游戏状态。

## 四、三条发布路径

| 方案 | 收益 | 工作量 | 风险与代价 | 结论 |
| --- | --- | --- | --- | --- |
| 全部仍维护自有代码前移 | 当前工具、所有保留测试和审阅工具均纳入，长期规则最完整 | 大：243个独立JS候选＋12个HTML逻辑＋Twee自有回调和已有TS收紧；先区分不可变历史夹具 | 很多时间花在未参与4.0交付的测试；更大CI/夹具迁移面，需要重新积累证据；不等于不能做 | 可选；若负责人要全仓先收口，应按此范围授权 |
| 当前交付链先完整约束 | 覆盖运行边界、实际验证系统、打包和维护工具，能直接改善4.0可信度 | 中到大：125个独立JS提案＋1个离线HTML逻辑＋Twee自有回调；已有TS约束同步补齐 | 仍涉及CI核心与测试；118个其它测试和11个预览页必须明确留待后续，不能宣传全仓完成 | **推荐前移此方案，完成后再发4.0** |
| 先发4.0后迁移 | 保留RC2已有验证，最快进入发行 | 当前新增迁移量最小；以后仍需处理同一批代码 | 明知有CJS→any和漏检TS仍继续，后续需再做一轮完整构建/制品验证 | 技术上可行，但不建议作为当前优先路线 |

本轮是源码评估，不以非空行数承诺准确工期。方案二最大的工作在测试/CI合同迁移，不在产品运行重写。建议用第一批实际迁移和原反例验证结果校准后续批次成本；遇到真实故障单独处理，不无限挂在语言迁移名下。

当前125文件由40个工具/检查和85个静态确认测试组成。静态依赖结果不证明所有动态载入都已执行；T0/T3必须以**固定的当前标准/研究声明和真实helper闭包**收口，不能因为文件不在85里就漏掉。反之也不把所有历史测试自动追加为新产品验收。

### 本批允许保留什么

1. 上游生成的 `src/wardrobe/vendor/isolated-model.js`：不手工改写上游算法。自有generator应转TS，边界有类型与必要校验；来源、许可和可重现生成保留。
2. 约定路径的CJS薄桥/启动产物：可以由CTS生成，不是手写JS的永久例外。现有 `scripts/ci-cases.cjs`也纳入本批TS来源评估。依赖安装前的启动限制须实测，若确需暂留手写JS，限定范围与退出条件；不能借桥保留一份复杂JS实现。
3. `tests/story/helpers.js`及原生HTML/Twee/恶意历史字串等夹具：作为目标环境/反例数据保留JS语义，由TS测试加载并验证。动态生成的非法代码不要求通过TS，否则会销毁反例价值。
4. ZIP/Loader要求的JS输出、Python打包/ZIP合同、Ruby仓库规则和YAML工作流保持各自语言。Python不是待迁移JS，没有必要为语言统一重写已经核对ZIP字节/元数据的工具。

**完成约束**：所有本批自有实现实际进入strict检查；没有新增ignore/nocheck、无依据any、关闭检查或批量双重断言；JSON/外部数据先unknown后校验；合法as const、经过证明的DOM断言和公开类型负例保留。类型纯迁移、运行时行为修复、可选整理分别提交；不借机换框架、弱化效果或改变Host/UI合同。

## 六、证据复用与必须重验

| 改动 | 可以复用 | 必须新做 |
