# EVO-V1-R8 — C5.1 雨势增强

2026-10-22，研究分支 `dev/evolution-4.0`，输入 `67b099f4f884f3d71ea362ab7c0b697aa3344549`。负责人观看C5后反馈：“雨滴需要更铿锵有力一些，整体速度加快，雨越大下的越多，下的越快”。本轮按整体雨势理解，既加强斜雨，也提高玻璃滑落滴补充和速度。C5.1仍待视觉裁决，不把技术通过视为效果认可；精确提交/最终CI见 [Issue #22](https://github.com/102326/DoL-Game-UI/issues/22) R8记录。

## 实际改动

| 编号 | 做了什么 | 保留什么 |
| --- | --- | --- |
| EVO-V1-R8-SHOWER | 从原第一方SVG派生 `shower-force.svg`，雨线半宽1.3倍/半长2.6倍、渐变更亮；最多三层错位雨幕，四档连续增加雨幕数量与下落速度 | 原3.x素材、原C5入口/媒体保留，非默认替换 |
| EVO-V1-R8-DROPS | 增加可选模型速度参数energy，增强路径随雨量提高加速度/速度上限；增加滑落补充、微滴密度 | 自然曲线、湿痕、合并、真正穿过底边才回收；原默认参数1保持原算法 |
| EVO-V1-R8-COMPARE | `shower=1&force=1`启用C5.1，`rain-force-review.html`提供原C5/增强C5.1同操作、四档雨量、雨转雪、1×原速对照 | 两段斜雨均开启、同控制行和1280×900/DPR1，不宣称播放器帧级同步 |
| CI-HANDOFF-01 / R8 | 补充模型负向证明、四档实际状态断言、像素/生命周期检查与当前交接 | 原CI检查名/触发及既有测试保留，不引入额外RAF/定时器/Canvas/绘图依赖 |

连续设计参数如下，不是气象/真实设备测量。原C3/C4/C5默认energy=1；增强路径energy=`1.05+.85×intensity`，加速度乘energy²、速度上限乘energy。补充系数`min(2,1.4×intensity)`，微滴可见候选`380×1.6×intensity`、池上限912；错位雨幕层权重总和`.75+1.5×intensity`，最后一层连续淡入。速度另以连续雨量提高，不靠缩小贴图制造“看似更密但实际更慢”。这些是视觉参数，不是物理流体求解。

滑落滴/总滴/轨迹/湿痕足迹上限仍7/90/900/32；雪晶与雪花绘制不变。每帧仍在原Canvas先画雨幕、清除实际文字/按钮保护区域，再画玻璃内容；保留移动布局保守保护、隐藏/减少动态/关闭释放。未改生产天气分类、设置V2.3、Host/API、业务/存档。

## 验证与证据

本机 macOS / Node24.18.0 / Chromium153.0.8010.12。新增第7项模型测试先在原模型失败：同一颗滑落滴的五档位移都为11.090962px；实现后默认与四档能量的位移严格递增，显式默认参数与旧默认逐帧相同，无效速度拒绝。

- `node --test tests/evolution-rain-model.test.cjs`：7项通过，保留原持续补充、自然湿痕、容量、有限坐标和干燥退出检查。
- `npx vue-tsc --noEmit -p tsconfig.evolution.json`，`npx vite build --config vite.evolution-weather.config.ts`：研究类型及构建。
- `node tests/evolution-weather-shower.cjs --force`：四档实际绘制微滴、雨幕速度/层权重、滑落补充/速度参数均严格递增；独立内容区像素开关检查排除工具条文字假阳性，正文/关闭按钮PNG严格一致；暂停/减少动态相位静止、390px、隐藏停止/释放重开。
- `node tests/evolution-weather-shower.cjs --force --record --baseline` 与 `--force --record`：两边均开启斜雨，分别原C5和增强C5.1；约1/7/13/19秒依次四档，25秒转雪、32秒截面后结束。实际等待保留，不剪辑加速。

原C5的 `--force --baseline` 使用原C5路径，不是关闭雨幕；原R7 `--baseline`仍用于斜雨关闭/开启对照。普通smoke按状态推进，不冒充原速。原C5/R7的成功CI只对应67b099f，不能代替本轮；最终R8按新提交另跑研究CI。

R8原速媒体、两组结果、独立内容区像素对照与源码/逐文件摘要在 `docs/media/evolution-weather-r8`。旧R5/R6/R7及其manifest保留历史身份。新增第十组16MiB媒体硬上限；160MiB是十组理论上限，不是实际体积，超限报错不截断，CI第一方Artifact保留14天。
