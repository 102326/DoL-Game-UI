# EVO-V1-R6 — C4 雨量与雪天

2026-10-22，研究分支 `dev/evolution-4.0`，输入 `9fa1fb0384624b522bef4576ed0e765b33bd9e7a`。负责人已认可 C3 雨滴和底边流出，并要求“之前不同雨量大小的效果也可以加回去，下雪的效果不明显”。本轮只完善隔离天气原型；C4 的雨量/雪天尚待负责人视觉评审。精确提交与实际 CI 身份见 [Issue #22](https://github.com/102326/DoL-Game-UI/issues/22) 的 R6 交付记录。

## 实际验证

本机 macOS / Node24.18.0 / 锁定 Chromium153.0.8010.12。模型先复现四档补充数量完全相同的预期失败 `[12,12,12,12]`，随后通过6项检查。新增第6项核对四档补充严格递增、默认参数保持原模型及无效参数拒绝。

- `node --test tests/evolution-rain-model.test.cjs`：6项通过。
- `npm run ci:check`：状态字段合同、项目/adapter/early/framework类型检查通过。
- `npx vue-tsc --noEmit -p tsconfig.evolution.json` 与 `npx vite build --config vite.evolution-weather.config.ts`：通过。
- `node tests/evolution-rain-glass.cjs --runoff`：原C3实际底边、正文保护及布局/分类/暂停/隐藏/390px/减少动态/关闭重开回归通过。
- `node tests/evolution-weather-levels.cjs`：四档实际绘制数量、连续雨雪状态、窗口像素变化、正文/关闭按钮像素、雪效静止/隐藏/390px/减少动态/释放重开通过。
- `node tests/evolution-weather-levels.cjs --record --baseline` 与 `--record`：同1280×900 / DPR1，均增加同一雨量操作行；依次晴、小雨、常规雨、大雨、强雨、雪、返回大雨。旧C3忽略雨量档位，保留其原有表现。录制实际等待，未剪辑加速；不宣称两播放器帧级同步。

首轮关闭按钮截图不一致，经诊断 Canvas 在按钮框内完全透明，差异来自按钮自身焦点背景/边框过渡。验证改为等待按钮自己的动画结束，并保持同一 Canvas 合成层、只清除绘制内容，再执行严格 PNG 相等断言；没有放宽阈值或修改产品动画。冰晶/雪花保护指标后续补齐，不以旧的仅雨滴指标证明雪效安全。7份冻结设置/球体/Hub/3.x Acrylic/天气提供者摘要一致。

媒体、源码摘要、逐文件体积与 SHA256 在 `docs/media/evolution-weather-r6{,-baseline}/manifest.json`；结果含实际操作时间、连续状态、运行环境与性能采样。源码身份按文件摘要核对，报告/HANDOFF的后续文字更新不冒充重新录制。

本机两组原速记录共24份媒体/结果、11,557,351字节（另有两份manifest）。C3/C4主视频分别53.48/53.44秒，来自独立录制，时长略有差异。逐文件摘要、两组源码身份与当前文件一致。构建后的画廊图片及两段视频加载、实际1×播放另已通过。

| 1×原速记录 | rAF中位 / p95 ms | JS绘制中位 / p95 ms |
| --- | --- | --- |
| C3 | 33.3 / 49.9 | 1.2 / 2.2 |
| C4 | 33.3 / 50.0 | 1.0 / 3.0 |

C4主录像四档实际绘制微滴为84 / 169 / 263 / 394；C3同四输入均263。稳定雪天截面为47个附着雪晶、12个飘雪，保守保护边界重叠数0；这是一个受控时刻，不是设备覆盖量或所有时刻的证明。帧率/绘制数值只描述此次录制，不声称性能优于C3。
