# Stone Free：Vue 分发对照

2026-10-17，基于 `67737b1c5a77a5beba443991f1522fc209332fe4`。本轮只研究消费者自带 Vue 和共享 Vue 的分发取舍。Done 是同源码构建、包体成本、代表性消费者行为、依赖缺失与局部失败，以及真实 ModLoader 加载；不改变默认分发、不操作 Android、不发布。

## 结论

**默认继续自带 Vue。** 本轮共享方案可以工作，但小规模安装没有明显交付收益。共享 Vue 保留为可选研究实现，暂不引入默认依赖或修改 Factory。

Vue 3.5.43 的完整公共导出运行库为 112,850 字节 JS，对照消费者原本各包含约 61–71 KB 的裁剪后 JS。共享方案减少重复代码，也失去按单个消费者裁剪整套公开导出的收益，并增加一个安装和版本协调点。

这是当前四个固定消费者的增量包体，不是整个 Mod 列表大小。两边不计未变的 Host 和纯领域包；README 使用相同文本，实际依赖元数据、许可证和额外运行库仍计入。对照 ZIP 只存在独立输出目录，不替换默认包。没有据此推断内存、启动时间、帧率或生态通用阈值。

## 实现与边界

`framework/experiments/shared-vue.ts` 只公开一份冻结的 Vue 公共导出入口。App、配置、状态与挂载仍由各消费者拥有，Host 无 Vue、不依赖官方 UI。没有把多个 Mod 合并到一个 App，也没有共享私有 Store。

对照构建直接复用现有四个消费者及 SDK 源码，只将 Vue 标为外部依赖并增加加载前检查。协议、构建所用 Vue 版本或所需导出不符时退出，不误用其它 Mod 的全局 Vue；依赖晚到不自动等待，须修正顺序再加载消费者。这是固定输入的实验保护，不是未来版本锁定政策。

退出运行库只删除自己的公开入口。已加载消费者持有导出引用，仍可能运行；**删除入口不等于运行库内存释放**。正常卸载先关闭消费者。外部占用和替换的命名空间保持原样。

代码与命令见 [实验说明](../framework/experiments/README.md)。独立输出为 `dist/framework-vue-comparison/`；用于注入失败组件的 `sdk-probe` 不进入任何 Mod ZIP，也不计入包体表。

## Validated

- `framework:vue:build`：框架 TS/Vue 检查、同配置默认构建、独立共享构建与五个对照 ZIP 验货通过。没有安装依赖或修改锁文件。
- `framework:vue:test`：9 组通过。同一阅读、比较、侧栏切换任务的观察结果一致；共享 SDK 创建的一个 App 失败/退出不会移除其它 App；撤销一个提供者不销毁其它消费者；依赖缺失、错误版本、缺导出、抛错的访问器和外部命名空间均有反例。
- 真实 DoL 0.5.12.13 / ModLoader 2.101.1 / SugarCube 2.36.1+34：五个 ZIP 依赖加载，三个独立 App 登记，两个公开视图和按需原值投影成立，没有官方 UI 或 MapleBirch。原年龄窗口挡住交互，未确认或绕过；结果是 `passed-with-limitations`。

证据：`tests/artifacts/stone-free-vue/browser-1792167647828/result.json`、`game-1792167670848/result.json`；详细字节和资源摘要位于 `dist/framework-vue-comparison/comparison.json`。浏览器结果保留运行当时的对照副本。两项运行之后只澄清了实验 README 并重新打包，ZIP 摘要/大小改变，JS、CSS 和依赖不变；未把最终包体称作同字节重新验收。

两个早期失败保留：`browser-1792167356114` 使用了错误按钮名；`browser-1792167380221` 用手写 App 装载模拟器，遗漏 SDK 在初次 render 失败后的清理复核。后者改为构建并调用真实 `framework/vue.ts` 后通过。两者属于项目测试问题，没有据此修改公共 Host/SDK 或认定共享 Vue 存在缺陷。

## Not validated / 后续决定

没有 Android、物理手机、真实 IME、原游戏跨 Passage、业务动作、性能和内存证据。当前构建只使用一个锁定 Vue 版本；第三方插件、不同 Vue 版本间接入和恶意修改公共导出不在保证范围。冻结外层导出不是安全沙箱，也不保证所有组件配置完全不可变。

本轮默认分发策略及 Host 核心行为未变，不重复 2.7 游戏回归及上一轮平板动作。Paisley Park Skill 的源码/构建路线足够，没有调用现场 CLI，也没有新增工具缺陷反馈。此前平板超时记录仍为 Unknown，本轮没有重跑或改写它。

若以后多个实际作者明确需要统一分发，再研究兼容版本区间与升级协商；不因当前三个消费者开始节省包体，就立即让独立作者强制安装共享运行库。
