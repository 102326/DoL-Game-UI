# Soft & Wet 4.5 — 研发记录（未发布）

2026-11-10，负责人要求以菱形玻璃球继续研发，同步GitHub，产品版本记为4.5。本记录不表示已经发布、合并main或通过实机验收；稳定发行仍为4.2。

## 本轮范围

- 正式入口采用蓝灰半透明玻璃、双层线框菱形和四向短刻线；圆形悬浮与主动停靠的窄条保持同一识别。球体暂用这一款外观。
- 普通展开、关闭不启动旧金属球的充能/余辉长演出，静止不持续绘制；展开轮廓提供短反馈，并隔离通用按钮圆角与旧金属焦点规则的覆盖。既有菜单运动、原生按钮、扇形/网格与内侧辅助操作继续工作。
- 拖动松手即保存当前位置，贴边也只停在可用区域内。停靠侧边由菜单显式执行。正式入口移除蓄力、弹射、瞄准线和尾迹；保留位置偏好、拖动取消、订阅和 Host 所有权。
- 玻璃关闭和不支持模糊时使用清晰的实色回退；系统减少动态继续生效。天气、窗口材质、设置和其它业务不改成另一套设计。
- 产品版本来源为`package.json`的4.5.0，锁文件根身份同步；Host协议、Host包及七个兼容包版本不随产品号提升。核心内部2.7版本保持既有独立合同。

## 自定义颜色主题与字体

「界面设置 → 材质 → 颜色与字体」提供五个颜色入口和本机字体设置。先在同页预览，选择「应用并保存」后同步到界面。选择「恢复默认外观」可回到既有黑灰 Acrylic 和默认字体。

- 可调界面底色、面板、主要文字、次要文字和强调色。首版在暗色材质内调色，过亮的底色或对比不足的前景会自动校正。预览展示选中、焦点和错误状态，语义提示仍使用原有色标。
- 填写本机已安装的字体名称。缺少字体或字形时由浏览器按系统字体栈回退，留空即使用原界面字体。字体资源由本机提供。
- 设置、悬浮工具菜单、属性、衣柜、商店及其它已接管的窗口共享外观偏好。已完整识别的兼容弹窗可继承外观。通透度、字号和间距仍使用各自的设置，玩家偏好保存在当前浏览器。

现存的「标题边缘纹样」只接入一组标题角色，「手机紧凑按钮间距」也只覆盖若干自有表单。下一轮先明确适用范围，再测属性、社交、存档标题及兼容弹窗。MapleBirch 与原版优化还可能同时识别同一存档根；Runtime 会保留先取得的样式归属，原版优化的日期修复只检查指纹 match。两种结构是否在真实版本同屏，以及日期修复是否应依赖样式归属，待组合样本核对。

建议先把设置的通用语义投射到**可测的呈现角色**（窗口外壳、阅读面板、行、主要控件、弹出菜单），允许原生动作、窄屏、设备和资源类适配采用各自结构。后续每个消费者用实际入口取计算样式与几何，覆盖主窗和 body portal，执行一次控件原生动作，并保留 partial／unknown 和退出回退。4.1 的尺寸、按键动效或某个主窗口绿灯不能代替该验证。

Host 候选沿用 [已有 HC 调查](evolution/EVO-4.1-HOST-SHARED-SURVEY-2026-10-26.md#4-候选及最小边界)：

- **先复用现有能力（HC-02）**。有 Host mount 的消费者可对照 `onScene`、Binding 与 `onCleanup`，逐个替换语义相同的场景监听。局部 DOM 重建、原节点恢复仍由对应 UI owner 处理。测试晚到 Host/jQuery、重入、旧回调失效与退出。
- **先在 UI Runtime 内量化（HC-04／05）**。[适配器](../src/runtime/ui.ts)每个登记项有两个 Observer 对象，十项齐全时可有二十个对象加一个偏好观察器；同帧合并后仍遍历已登记项。先测不同入口的实际活跃数、无关变更触发的查询和刷新耗时，再考虑精准刷新集合。窗口动效的环境通知可在 UI 层做小范围共享，继续由各 owner 取消动画和释放资源。
- **条件明确后再评审 Host 扩展（HC-03／06）**。若有多个独立消费者需要挂载之外的根级清理，再评审通用清理入口。另可在固定 1／10／100 受控挂载场景测 [Host 祖先观察索引](../framework/host.ts)的重建成本，确认断开后取消与租约释放仍及时。当前无性能收益实测。
- UI 的主题、CSS token、偏好、组件与业务、第三方指纹留在产品和兼容层。独立组件 E32 为另一研究分支的证据。4.5 本批继续独立打包 Host 与官方 UI，公共协议、分发、业务与生命周期行为无变更。

### 4.5 内部结构改造建议（2026-11-18，字体与字号首批已实施）

本次按 `2484b33` 的实际调用链做静态调查。建议一次确定公共行为的归属，再按完整用户操作迁移。首批集中 UI 偏好及其呈现，保留现有外部入口和存储格式。下表保留完整迁移方向。已实施部分及本机验证范围见交接文档，其余按后续切片推进。

| 源码证据 | 建议归属与改法 |
| --- | --- |
| [启动与公开 API](../src/main.ts)先初始化 master，再启动各页和主题。公开读接口拼接各页状态，写接口按字符串选择各页 setter。[master](../src/runtime/master.ts)与[主题控制器](../src/theme/controller.ts)分别解析同一存储项。设置页打开、持久化、尺寸变化也会进入主题控制器的整组投影。 | 在 UI 启动入口创建唯一的偏好服务，先加载再启动页面。集中类型、校验、旧数据迁移、持久化和变更通知。第一批沿用旧 key；每迁入一个键，同次移除旧读写者。Vue 设置面板只持草稿、消息和可订阅的快照。按变更键投影到颜色/字体、阅读、页面启用等实际消费者；尺寸变化只重算受尺寸影响的表现。 |

| [设置对话框](../src/theme/controller.ts)管理可中断关闭、无原生 dialog 时的回退和事件隔离；[公共弹窗](../src/runtime/surfaces.ts)要求调用方提供新建且脱离文档的节点，区分关闭原因；[工作区登记](../src/ui/workspace-surface.ts)只登记已有窗口并释放呈现资源。 | 共享 UI 外壳的标题、正文、操作区角色、滚动边界、原生控件样式及可复用的焦点处理。保留不同容器的挂载、关闭和内容所有权。严禁为了套壳搬走第三方原生节点。 |

**实施顺序与旧路径退出条件**

1. 先固定现有外部行为。用旧格式偏好、存储不可写、模块缺席、页面故障重试、衣柜忙时拒绝及主题失效恢复作为对照。首个纵切选自定义字体与字号，贯穿设置、Hub 自有详情外壳、调用方内容、ModHub 动态弹窗。检查修改前已打开、修改后才打开以及重置重开三种情况。
2. 将总开关和各页启用设置按同一内部接口迁入，逐项保留原通知时机或验证等价行为。完成条件为设置页与公开 API 对同一操作得到一致的结果，每个已迁移键只有一个持久化写者，页面恢复和拒绝分支仍有效。外部兼容转发可以长期保留。
3. 在上述真实入口复用布局和角色样式，再迁移其它自有窗口与已审核的兼容角色。以窄屏、150% 字号、长标题、可滚正文、可达关闭按钮和一次原生操作检查结果；完整匹配、部分匹配、卸载后恢复分别核对。每一批删去已被替代的私有覆盖规则。
4. 性能对照取同一次应用字体、改变窗口尺寸和打开弹窗，记录无关页面刷新数、样式写入次数及到下一次可交互绘制的时间。只有实际热点再进入调度优化。Host 保留现有 Binding、scene、撤销和资源所有权；新增跨包协议走前述 HC 调查。
