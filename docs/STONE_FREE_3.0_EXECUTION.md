## 基线与首轮 Done

基于正式 UI 2.7.0 提交 `965afcf119260886319f5beb6616362acb306a09`，隔离分支 `research/stone-free-3.0-framework`。原工作区清洁，正式 2.7 源码、制品、偏好与 API v1 保留。Paisley Park 已安装的 resolver 指向 6.1.0 White Snake，相关交付已完成，满足原规划的前置顺序。

首轮交付是 A/B 工程原型：无官方 UI 的公共 Host + 独立 Vue 消费者；同一公开状态来源的独立对照视图与可选官方 Drawer 消费者；挂载、场景代次、异步失效、资源冲突和释放的定向反例；独立离线 ZIP、最小作者配方与代表性真实 DoL 检查。它不是全部 3.0 的发布验收，不自动包含所有候选玩家功能。

验证重点是 Runtime 生命周期及所有权，按高风险做定向生命周期/集成检查，不重复整个 2.7 Gameplay 回归。尽可能利用已授权 Android 独立测试实例，只读采样，不修改玩家存档。实际真机可用性与各次结果另记，桌面夹具不称作 Android 证据。

## 事实与方案

现有 `src/runtime/ui.ts` 和 `surfaces.ts` 的能力依赖 `data-dol-midnight`；只把它们改名拆包不能证明独立使用。现有 Vue App 和 DOM 所有权经验可继承，UI API v1 不改为 Framework 新协议。

首轮 Host 无 Vue、主题、全局输入管理及游戏状态同步。消费者自带当前 Vue，便于隔离 App 和实验分发；共享 Vue Runtime 仍为比较项，不提前冻结物理包结构。资源租约只管理提交的资源；原生 dialog、区域布局与按键策略留给消费者/布局提供者。投影只接受受限 JSON；业务动作接口等有实际消费者后再评估。

首轮使用原版三个状态字段作为一个有限 Domain Adapter，第二个消费者只认识公开 schema，并提出“当前/基线对照”的新呈现，不修改提供者私有代码。两个消费者同属本工程编写，不能据此宣称独立社区采用。

## 后续决策

A/B 证据成立后，再决定 Host/SDK 的稳定合同与分发、官方 UI 是否采用此接缝及最小 Factory 配方。Factory 需要对照普通模板的二次修改和 SDK 升级，不预建画布或覆盖作者源码。Widget、自由布局及业务动作实验按证据选取，不将候选清单全部变为同版承诺。

首轮已实现源码配方的生成与受保护 SDK 更新实验，未证明相对模板的通用效率收益；既有 UI API v1 以独立可选消费者接入，不反向依赖实验 Host。[验证记录](STONE_FREE_3.0_VALIDATION.md)分别说明 A/B 初步结论和后续范围；[Tools 使用反馈](STONE_FREE_3.0_PAISLEY_FEEDBACK.md)只记录真实摩擦。

无本轮发布授权：不推送、合并、打标签或创建 Release。
