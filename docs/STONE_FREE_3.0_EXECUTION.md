## 基线与首轮 Done

基于正式 UI 2.7.0 提交 `965afcf119260886319f5beb6616362acb306a09`，隔离分支 `research/stone-free-3.0-framework`。原工作区清洁，正式 2.7 源码、制品、偏好与 API v1 保留。Paisley Park 已安装的 resolver 指向 6.1.0 White Snake，相关交付已完成，满足原规划的前置顺序。

首轮交付是 A/B 工程原型：无官方 UI 的公共 Host + 独立 Vue 消费者；同一公开状态来源的独立对照视图与可选官方 Drawer 消费者；挂载、场景代次、异步失效、资源冲突和释放的定向反例；独立离线 ZIP、最小作者配方与代表性真实 DoL 检查。它不是全部 3.0 的发布验收，不自动包含所有候选玩家功能。

验证重点是 Runtime 生命周期及所有权，按高风险做定向生命周期/集成检查，不重复整个 2.7 Gameplay 回归。尽可能利用已授权 Android 独立测试实例，只读采样，不修改玩家存档。实际真机可用性与各次结果另记，桌面夹具不称作 Android 证据。

## 事实与方案

现有 `src/runtime/ui.ts` 和 `surfaces.ts` 的能力依赖 `data-dol-midnight`；只把它们改名拆包不能证明独立使用。现有 Vue App 和 DOM 所有权经验可继承，UI API v1 不改为 Framework 新协议。

首轮 Host 无 Vue、主题、全局输入管理及游戏状态同步。消费者自带当前 Vue，便于隔离 App 和实验分发；共享 Vue Runtime 仍为比较项，不提前冻结物理包结构。资源租约只管理提交的资源；原生 dialog、区域布局与按键策略留给消费者/布局提供者。投影只接受受限 JSON；业务动作接口等有实际消费者后再评估。

首轮使用原版三个状态字段作为一个有限 Domain Adapter，第二个消费者只认识公开 schema，并提出“当前/基线对照”的新呈现，不修改提供者私有代码。两个消费者同属本工程编写，不能据此宣称独立社区采用。

## 后续决策

A/B 证据成立后，再决定 Host/SDK 的稳定合同与分发、官方 UI 是否采用此接缝及最小 Factory 配方。Factory 需要对照普通模板的二次修改和 SDK 升级，不预建画布或覆盖作者源码。Widget、自由布局及业务动作实验按证据选取，不将候选清单全部变为同版承诺。

首轮已实现源码配方的生成与受保护 SDK 更新实验，未证明相对模板的通用效率收益；既有 UI API v1 以独立可选消费者接入，不反向依赖实验 Host。[验证记录](STONE_FREE_3.0_VALIDATION.md)分别说明 A/B 初步结论和后续范围；[Tools 使用反馈](STONE_FREE_3.0_PAISLEY_FEEDBACK.md)只记录真实摩擦。

无本轮发布授权：不推送、合并、打标签或创建 Release。

## 第二轮：视图贡献与信息工作台

用户继续授权后，新增可选视图合同与有限布局提供者。两个研究 Mod 贡献视图；工作台只组织贡献的自有内容，支持隐藏、排序与密度偏好。替代布局只用于两个真实打包参与者的区域/快捷键/模态争用验证，不作为另一个正式 UI。

本轮同时修正临时部署的卸载边界：Host 退出不等于包卸载，入口导出的清理函数需要被调用。结果、失败与限制见[工作台记录](STONE_FREE_3.0_WORKSPACE.md)；首轮记录保留其当时范围，不因后续结果改写。

## 第三轮：受审 UI 操作

继续授权后，以原版侧栏切换验证公开命令和独立消费者：来源仍由 SugarCube 拥有，Host 只核对声明、绑定及返回见证，发生不确定性不重试。模态内的工作台视图不会越过模态调用原控件。本轮不含购买、穿戴或存档动作，详见[阅读空间记录](STONE_FREE_3.0_READING.md)。

## 第四轮：Vue 分发取舍

用同一消费者源码对照自带 Vue 与共享运行库。共享实现独立输出，验证读取/比较/原侧栏任务、依赖退让、App 局部失败及真实 Loader 加载；不操作设备，也不扩大游戏业务。当前固定样本下三个以上消费者出现包体收益，但共享依赖和升级成本仍存在，因此默认保持自带 Vue，Factory 不改变。结果与未覆盖范围见[分发对照](STONE_FREE_3.0_VUE_DISTRIBUTION.md)。

## 第五轮：作者工作流与非模态布局

继续完成 Factory 的真实 SFC 预览、二次修改、只读 SDK 检查、实际历史 SDK 升级及旧 Host 退让；将现有替代工作台改为非模态侧边布局，让同一公开视图在原页面仍可交互时使用。复用既有区域/按键租约，不增加 Host 状态或全局输入管理。构建、Factory 18 组、工作台 12 组、命令 13 组通过；平板临时加载确认原侧栏操作、模态退让与清理。失败收据及未覆盖范围见[作者工作流记录](STONE_FREE_3.0_AUTHOR_WORKFLOW.md)。本轮完成不等于全部 3.0 已达到发布条件。

## 第六轮：官方外壳使用公开贡献

将可选 `StoneFreeSoftWetSurface` 从固定状态快照改为通用贡献视图消费者，复用现有 `ViewOutlet` 和官方 Drawer API v1，不修改 Host、SDK 或正式 UI。覆盖来源撤销、同名新声明、局部失败、异步迟到、场景失效、主题关闭和多布局实例隔离；构建、32 组基础/接入检查与平板临时加载通过。详见[官方外壳接入记录](STONE_FREE_3.0_OFFICIAL_VIEWS.md)。仍保留各消费者自带 Vue，不因此决定正式包拆分或整体 UI 迁移。

## 第七轮：局部恢复与独立作者源码包

补齐工作台“恢复本布局”，只重置该布局的显示偏好；验证其它布局、作者对照状态和游戏原值不受影响，存储拒绝时仍可本次恢复。另导出 12 文件的独立作者源码包，实际从解压制品创建、修改、检查 SDK、构建并运行作者 Mod，不依赖完整 UI 源码。新增[作者指南](STONE_FREE_3.0_AUTHOR_GUIDE.md)，协议与正式 UI API 不变。工作台 14 组、作者源码包 4 组及平板代表性组合通过；边界、失败和证据见[本轮记录](STONE_FREE_3.0_RECOVERY_AND_KIT.md)。
