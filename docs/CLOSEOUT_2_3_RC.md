## 新服装类型的支持边界

| 场景 | 发现 / 展示 / 信息 | 操作与回退 |
| --- | --- | --- |
| 原衣槽新增普通衣物 | 从当前原库存、定义、列表投影读取，不依赖静态物品白名单 | 原操作新鲜度校验后执行；未知附加内容保留原入口。隔离购买→新增库存→穿戴链验证 |
| 真正新增槽位，沿用类似结构 | cape / charm（含空槽）夹具独立验证发现、注册、展示资格、撤销及不可变查询，非 ReOverfits 三槽证明 | 原版固定部位宏不会因为数组存在而自动支持新槽。必须由作者提供完整原操作合同；本轮没有证明任意新槽都可穿戴/整理 |
| 私有库存、定义或专属操作 | 不读取任意私有状态，不猜业务映射；数据不足给明确不支持原因 | 保留原版/第三方入口和未知 DOM。需要作者接入，Core 不接管或提供任意回调 |

商店以目标已输出的原类别/商品 DOM 为来源。新增原商品和未知分类不被静默删除；“衣柜能发现槽位”不意味着商店或原穿戴宏已实现相同槽位。具体合同见 UI_RUNTIME.md。
