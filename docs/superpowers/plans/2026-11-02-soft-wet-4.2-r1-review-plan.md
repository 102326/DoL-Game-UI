当前P-A外缘和P-B余像过于保守，不能称为已有辨识度的视觉成果。保留真实组件、原速对照、输入中断/释放和最小天气探针；下一小样应让材质层次与运动因果肉眼可辨，实际球体位置和命中一致，不能继续用装饰余像代替惯性/召回。

### V1.2 执行边界（负责人本轮确认）

四个设计方向是帮助选择的小样，可组合，不做四套完整产品。初步可操作后立即做一窗口/一天气/一次拖动的联合探针，记录文字、合成/重绘、坐标和渲染来源；完整四档/雨雪霜/特殊天空P-C仍后置。小样有区分力后再按选择补第二角色和完整中断验证，不把所有方向都铺满。

需求发现覆盖Hub之外：记录实际操作痛点，逐项比较默认改进、是否需要选择、维护/恢复成本，允许零新增设置。CI复用catalog/依赖/事实源；C0–C4是可交错工作包，不是五道审批关卡，不为每批新增协议或材料层。先完成成本/报告样本与薄映射，再提出一个最小隔离实现，未批准整套迁移。

影子对照固定为一组有界代表性输入与历史负例，具体样本/结束条件见本批研究记录；不永久双跑全量。效率以每个有效变更的实际等待、运行次数、修复轮数、首次可行动反馈、到可集成结论总时间衡量，按风险/档位比较；未知数据不得估填。

本计划承接 [4.2 R0 调查](../../evolution/EVO-4.2-R0-2026-11-02.md) 与 [综合交接原文](../../references/SOFT_WET_4.2_RESEARCH_HANDOFF_2026-11-02.md)，将其中候选排成可执行、可退出的研究批次。R0保存事实与证据，本文负责范围与顺序，[首批执行记录](../../evolution/EVO-4.2-R1-2026-11-02.md)记录结果，不另建路线图。CI依据 [精准选测与集中播报补充决议](../../references/MOODY_CI_TARGETED_COLLECT_DECISION_2026-11-02.md)。此前V1.1只获准核对与修订；本轮联合评审正式批准下述小样和研究，未批准正式CI迁移或发布。

## 一、目标与基本判断

本轮要验证：在保留黑灰 Acrylic 偏好的基础上，能否让窗口更精致、操控更直接、环境与材质更可信，并且不给常用操作增加强制等待。快速流畅、华丽精致、感知自然同时评价，不预设减少特效就是优化。

4.1.0是正式产品对照，不继续修改其Release。研究基线为main `c7d8bac67fd04d0a81e59cf4c49800a510a39a11`，与Tag `v4.1.0`（`9c26b00`）文件树一致。实施前再次核对远端、工作区和实际运行环境；若基线变化，记录差异后判断是否影响对照，不覆盖本地工作。

我的建议是：**先用真实窗口与Hub建立可操作的设计成果；CI同时做成本拆账和消费者映射。联合天气样片随后决定，大型CI重构与Host扩展均不作为视觉研究前置。**

## 三、实施顺序与评审点

### M0：固定对照与验证边界

1. 安全核对基线、未提交工作、工具和锁定依赖。项目固定Node26.12.1，本机先前查到26.13.0；正式采样优先使用项目固定版本，不能把旧环境结果当新环境已通过。
2. 独立研究分支/工作目录保留4.1对照。原型优先使用TS、真实Vue组件和必要生产样式；合成业务数据，不复制整套游戏到公开材料。
3. 定义操作脚本和观测时点：输入到达、处理结束、首个反馈、可操作、视觉收束、取消与释放。UI开关/颜色/动画参数之外，输入内容与业务动作保持可比较。
4. 静态检查与受影响原有合同先跑通，再进入候选。若基线本身失败，保存失败并区分夹具/环境/产品，不临时弱化断言。

**检查点：**对照可信、输入隔离、记录可追溯即可进入研究，不要求先跑一轮发行级CI。

### M1：P-A窗口研究，优先交付可见成果

实际路径：打开设置→阅读长说明→操作开关、滑杆、下拉框→切分类→立即关闭重开；再在商店详情角色验证同一视觉语言。使用合成商品数据，不执行购买。

| 方向 | 视觉和交互重点 | 最关键的未知 |
| --- | --- | --- |
| A「静态玻璃＋局部湿光」 | 沿用原方案Quartz烟色厚度、暖冷双边光、阅读井与层次；局部指针湿光为当前新增表达，须单独判断价值 | 静止长看是否比4.1更精致，复杂背景下是否仍舒服；不能只有指针高光变化 |
| B「受力材质」 | 沿用原方案硬壳、内芯滞后、逆速度光带、世界光源固定与有限应变；调整为所选实际窗口的操作路径 | 内芯/外壳是否具有可见而可信的关系，文字/命中是否一致；不把装饰外缘等同完整受力材质 |

先用少量关键场景做两方向探索，不为凑候选把所有窗口完整制作两遍。获得区分力后，选有价值的方向补第二角色与中断合同；未入选方向保存理由和复现入口。两方向的样片不预设赢家，也不自动形成两套产品皮肤。

输出：可操作页面、静止/稳定动态状态、同视口同操作原速新旧录像、正文/控件近景、关键几何和资源结果。用户可直接操作，录像不能替代原型。

**检查点：**负责人判断方向；工程侧报告可用性和成本。若只是更花但没有体验收益，继续调整或停止该方向；不能以测试全绿宣布画质通过。

### M2：P-B Hub运动研究（JELLY仅为运动子项）

保留真实MotionHub工具动作、焦点、取消与安全回退以及4.1对照；位置策略允许在隔离原型中调整为自由悬浮，不把旧side/y/docked实现当作不可变产品边界。分别探索：

- **A「软芯贴手」**：沿用原方案球体定向高光、刻线自旋与可中断跟手；把模块软芯概念借到Hub是调整/新增，不冒称原球已有软芯。先做到自由拖放和直接反馈，比较有限形变是否适合球体。
- **B「约束惯性＋丝线召回」**：沿用有限惯性与锚点→延线→绷紧→牵引的因果关系，实际球体移动且可重新抓取；调整为自由落定，不以侧边作为必达终点。丝线用于明确的归位/召回意图，不每次放手强制演出。蓄力/自旋/尾迹保留独立实验价值，不默认引入撞开业务窗口或整场景物理。

A/B可组合，先把自由悬浮与核心运动做清楚，再比较惯性/召回是否有价值。原包模块编辑态禁用内容以避免命中偏差，不能直接照搬成日常窗口必须锁住全部控件；可在拖动手柄的受控交互期研究，结束后立即恢复。视觉/布局/动画内部实现可重做，不被现有轻微外缘实现限制。

自由悬浮需补：中央/四角停留、菜单按可用空间展开、拖放不误激活工具、键盘可到达、遮挡后的找回、旋转/缩放/安全区约束及旧停靠位置读取。原side/y/docked不能表达完整二维位置；候选用隔离位置模型验证，生产存储迁移另核对旧数据与回退，不改Host协议。高频物理量只在内存，落定/显式操作才保存；取消不写入半程位置。

先比较默认布局与容错，不新增玩家设置。若快捷项选择/排序确有重复任务依据，再单独提交有限自定义研究卡，允许最终零新增。

必经场景：中央及边缘展开选项、快速反向、自由拖放、显式停靠/越界恢复对照、拖动中取消、召回中重新抓住、隐藏/恢复、键盘选择、失焦、场景失效、视口旋转与缩放、低帧率输入。分别追踪逻辑状态、视觉clock、临时姿态和保存位置；不把物理姿态逐帧写入永久布局。

**检查点：**动作恰好一次；隐藏内容不可被键盘激活；关闭后不阻挡；取消/销毁后无迟到回调夺权及资源残留。历史线索需先复现，不能一开始就按已确认产品缺陷修改。

### M3：P-C联合样片，另设进入决定

当P-A/P-B有值得保留的方向后，再决定是否制作同一窗口的晴雨、四档雨量、雨雪霜、昼夜及一种特殊天空，与拖动受力联动。

对照保留4.1、仅材质变化、仅受力变化、联合效果四条件，固定seed/天气序列/操作/时长。重点观察水滴附着与流出、光照/湿痕与受力关系、正文保护、长期静止观看和联合重绘成本。

GL等技术可研究，但先验证实际背景来源；受控图像折射成功不证明可以取得实时DOM纹理。不以全屏粒子覆盖冒充材质融合，不因Canvas已实现而禁止其他路线。

**此项是后续提案，不在建议首批默认实施范围。**

### 4.2 少量影响映射：先人工可审，不建复杂选择器

复用现有catalog、family/dependencies和锁中的检查/用例标识；只增加能够解释消费者关系的薄映射。下表为**候选组**，不是已经冻结的精确清单；实施前逐项绑定现有entry/case和构建前置，名称相同不代表可互换。

| 影响组及源码示例 | 至少研究覆盖的现有检查/消费者 | 扩围/不适用边界 |
| --- | --- | --- |
| 非打包规划文档 | 链接/格式/身份一致性 | README、玩家docs、NOTICE/许可证等实际被打包的文档另做包合同；不能按.md后缀统一免测 |
| 独立材质参数：acrylic / CSS | 默认值、材质/可读性、设置及实际受影响兼容角色 | 选择器、布局/模糊/命中变化扩大到间接窗口和几何；仅独立色值不回放全部历史天气 |
| 共享窗口/输入/偏好：navigation、source-motion、UI runtime | 设置、属性/社交/通用面板、受影响独立窗口/适配器、焦点/命中、历史中断/释放 | 核心改动或影响集合不能证明完整时扩大，必要时全量；不能只测被改窗口 |
| Hub：MotionHub / golden-spin | 工具动作、指针/触摸/键盘、geometry、input/lifecycle、停靠/缩放/方向/隐藏恢复 | 共享输入/布局组件变化并入上一组；独立球体外观不自动要求所有旧窗口实验 |
| 天气/前景：surface、wet-glass、foreground-plane | 模型/四档雨/雪、header/special、DOM写入、可见时钟、原生节点/各适用surface、资源释放 | 生产重导出的历史变体保留独有故障模型；晴天局部色值不能类比共享renderer修改 |
| 业务及兼容：saves/shop/wardrobe/combat、compat | 对应数据/原动作/失败恢复/生命周期与目标包合同；共享API的直接和间接消费者 | 不无差别波及所有Mod；实际存档/交易等必要宿主验证仍按任务要求 |
| ModHub规则优化：early/cache/rewrite | 精确版本/源码匹配、输入变化/容量/隔离、迟到结果及不匹配回退 | 不把style adapter检查当依赖算法证明，不沿用旧1.8.3结果替1.9.2 |
| 构建/依赖/打包/Host核心/CI规则自身 | 包成员/版本/依赖/许可、独立重建及影响到的公共协议、选测/证据/门禁反例 | 根据实际风险保守扩围；未知映射、无法取得可靠基线或选测规则变化默认完整验证 |

选中集合 = 直接匹配检查 ∪ 已知间接消费者回归 ∪ 构建/夹具/环境前置依赖闭包 ∪ 本轮明确必需的历史负例。重命名和删除同时看旧/新路径；基线不可解析、未知文件、映射矛盾或新消费者缺映射时不静默忽略。共享核心不一定无条件全量，但必须说明闭包充分性；不能判断就保守全量。

PR使用实际base/head/merge输入，本地使用明确基线并纳入未提交/新增/删除输入；不只按head SHA去重。计划包含选择规则版本/摘要、影响基线与实际源码身份、预期case和证据集合、选中理由及不适用理由，并与Run/Attempt/配置/锁定依赖绑定。独立核验器在可信规则和真实差异下核对，不把任意producer清单当授权排除证明。

### 4.3 三种执行意图与封板后差异复测

这些是提议的**运行意图**，不要求新增三个复杂平台或立即改现profile名。

| 意图 | 拟选范围 | 完成条件 |
| --- | --- | --- |
| 日常 / PR / 普通RC | 影响闭包＋必要基础/负例；只因具体风险扩大，不按“RC”名称自动全量 | 本轮所有选中必需项实际完成且通过，范围/不适用理由与证据完整，真实PR门禁成立 |
| 大版本最后封板 | 固定本版本现役支持的产品/消费者、包合同、适用研究回归、完整约定布局及防御反例；必要实机/视觉另验 | 冻结最终源码/制品及完整集合；未成熟实验不能凭历史存在进入发布承诺。所有适用必需项通过并取得负责人批准 |
| 封板后修复复测 | 相对已封板输入的差异＋直接/间接影响＋重建产物和必要包合同；改变证据适用性时重新全量 | 明确哪些旧结果沿用、哪些由新SHA/制品结果替换；旧Run保持旧身份，不改写成覆盖新提交 |

差异很小也必须有相应新身份/产物证据；仅无关文档改变不机械使产品证据失效。普通RC不默认全量不等于自行放宽当前尚未迁移的候选政策，需先批准具体替换范围。

### 4.4 执行和报告规则

- 每个已选检查先验证前置结果和可用输入：满足即执行；前置失败/缺失时标BLOCKED并关联阻塞链；独立失败不终止其他可执行检查。
- 单项超时隔离该项/子进程及其后继；整轮预算耗尽后剩余项标未运行。致命环境、资源耗尽或安全风险停止不可用分支，保留首个原因；仍安全且独立的分支继续。
- 不引入自动重试至绿。确需重试时保留原失败、理由和每次结果；取消/断流不能汇总为通过。
- 新报告术语可使用BLOCKED/NOT_RUN；现有顶层Status枚举没有BLOCKED，通过rawStatus/caseStatus表达。本轮不改枚举，未来迁移不能只加显示文案而忽略旧schema/聚合兼容。
- 最终gate仍根据所有选中必需项、证据和计划完整性判定。报告去重不会抹去失败项；减少播报次数不会让红灯通过。

集中报告建议结构：

1. **范围**：已选必需、已执行、通过、失败/执行错误、阻塞、未运行/取消、结果不确定、不适用，各有去重清单和理由。以唯一check ID为统计单位，内部case单独列；每个已选项只进入一个终态桶。已选总数=通过＋失败/错误＋阻塞＋未运行/取消＋结果不确定；已执行为其中实际启动的项，另列，不能再相加。未选中“不适用”不计为PASS。
2. **根因组**：已确认原因、暂定关联与Unknown分开，分类为产品/夹具/基础设施/未判定；主失败及被阻塞链分开。相同错误文字或同一退出码不能直接证明同根因；一项可关联多原因，缺少报告只在有证据时列为某根因下游。
3. **证据与行动**：每组保留原check、实际源码/Run/Attempt/操作输入、关键日志或截图、复现条件、建议修法与定向复测集合。聚合只压缩重复呈现，不删除原结果。
4. **整体结论**：本轮哪些必需项失败/未完成、哪些证据可复用、是否仍阻止下一阶段；范围不是全量就明确写范围。

### 4.5 拆成独立批准批次，保留回退

| 批次 | 修改候选 | 必需负向验收 | 回退 / 权限 |
| --- | --- | --- | --- |
| C0 账本和报告样本 | 既有日志/结果离线分析；必要时另提最小计时方案 | 同一根因多下游不多算缺陷、Unknown不强行分类、统计守恒 | 本次只完成现状核对和方案；新工具/runner计时需明确批准 |
| C1 影响映射和计划原型 | catalog/dependencies附近的薄映射与计划生成提案；先影子比对，不改变门禁 | 间接消费者遗漏、rename/delete、未知路径、缺前置、错误base/merge、篡改排除理由 | 规则不明回到现完整路径；另行批准隔离实现，不能只用子集参数替代计划合同 |

精准选测必需的“范围身份”变更与C4的大范围协议简化不同；前者是安全接入子集的最小前提，不能为了坚持“协议最后做”而遗漏它。无需同时重写所有证据格式。

## 五、验证、比较与采用标准

| 维度 | 如何判断 | 不足以证明什么 |
| --- | --- | --- |
| 视觉 | 可操作预览＋同操作原速对照＋负责人裁决；静止/动态/可读性共同看 | 截图好看或自动化PASS不等于视觉通过 |
| 行为 | 原生事件单次、控件/焦点、取消/恢复、失效/清理定向合同 | 合成数据不等于真实存档/购买/穿戴/战斗验收 |
| 响应 | 首次加载/首次打开/再次打开分开，输入等待/处理/反馈/可操作分别报告 | 回调结束和首个rAF不证明实际上屏或物理触控延迟 |
| 性能 | 固定输入、交错对照、保留慢样本/负结果，trace归因与无探针计时分开 | 少Observer、少绘制或少代码不直接证明端到端变快 |
| 资源 | 空闲/隐藏/关闭/反复开关/中断后检查活跃帧、计时器、订阅和DOM | 一次关闭正常不等于长期内存或功耗通过 |
| 兼容 | 代表布局、字号、触摸/键盘/reduced-motion、未知结构/渲染失败回退 | Chromium模拟不等于Windows原生弹窗、Android WebView或全设备验收 |
| CI效率 | 同风险/事件/profile的可比批次，成本与缺陷发现能力一起比较 | 单次更快或旧实验未失败，不足以支持降频/删除 |

性能采样先用少量样本确认计时点/输入可比，再对有价值候选扩大；R0提议warm30对、cold10次可作为正式比较起点，实施前按具体问题与设备成本确定，不成为每次小改的固定负担。分位数与异常处理在采样前约定，保留原始数字与身份，不事后挑好看结果。

20ms是限定场景研究目标，不是全产品硬门槛或行业INP标准。Windows Edge与Android WebView尽早验证最容易推翻方案的输入/呈现假设；设备暂不可用时可继续隔离原型，相关路线的技术结论保持暂定，不能直接进入正式采用。

采用某候选需要：负责人认可能感知的收益；关键行为与失败恢复成立；成本有依据、负结果已披露；目标宿主可行。达不到则调整、留研究或不采用。不得以默认自动降质、缩减有效断言或减小业务范围制造成功。

## 六、跨窗口、Host与版本边界

首批先做设置，方向选定后补商店详情的第二结构，不代表全局推广。后续若选中方案，必须沿用 [消费者覆盖表](../../evolution/EVO-P0-COVERAGE.md)，逐行核对设置、属性/社交/通用面板、存档、衣柜/参考/抽屉、商店、战斗和维护中的兼容页面：外壳、导航/控件/状态、文字/间距、动效/天气、偏好、原生行为、回退与释放。

不同实现可以保留，但表现需对齐同一视觉语言，角色差异须说明；不能再出现“设置更新成功便算全局完成”。正式迁移分批退出旧路径，最终以同一个集成源码和实际制品验收。

Host先复用现有Participant/Mount/Binding/Source/View/Command。新增公共能力必须由真实多消费者需求和可验证收益推动；UI材质/动作表现、第三方业务、ModHub依赖推断不因本研究自动上移。规则缓存和玻璃分层已经进入4.1，不重复当作新任务。

## 七、交付、回退与评审问题

每个研究批次交付：源码/环境身份、可运行入口、原速对照、定向检查和关键性能结果、失败与Unknown、采用/继续/不采用建议，更新现有HANDOFF。Git交付按单独确认的提交/推送范围执行；原日志、trace、机器绝对路径及私人材料不默认上传。

每个原型都能退出回到独立4.1对照；保留研究结果和被否决原因，不改变已发布ZIP或Tag。原型成果、自动化通过、视觉认可、真实宿主验证、正式集成和可发布状态分开记录。

负责人和小鸥已确认：首批M0＋P-A＋P-B，四方向做小样且可以组合；提前做一窗口/一天气/一次拖动探针，完整P-C后置；CI先成本/报告/薄映射研究再选最小隔离实现，C0–C4不一次性放行；早期Windows/Android验证保留，设备暂缺不阻止隔离原型；Host不先扩容、默认不自动降质、允许零新增，同时保留非Hub需求发现。

小样完成后按视觉方向选择补第二角色与相应中断验证，不自动推广所有窗口。实施结果、实际验证和仍待事项更新首批记录与HANDOFF；不据本计划推导main合并、4.2完整功能、发行日期或发布授权。
