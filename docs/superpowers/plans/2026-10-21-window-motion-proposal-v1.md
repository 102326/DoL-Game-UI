# #22 下一步窗口运动方案草案 V1

状态：**负责人已授权一版设置原型与同操作、同视口、原速新旧对照；视觉结果待验收。** 原型隔离在[settings-refraction-v1](../../../prototypes/settings-refraction-v1/README.md)，不推广其它窗口、不合并main、不发布。依据[正式口径](../../SOFT_WET_3.1_PRODUCT_DIRECTION_V1.md)及[报告原文](../../references/SOFT_WET_3.1_VISUAL_MOTION_V1_ORIGINAL.md)，不以b507的“更短、更轻”作为后续默认方向。

## 建议先做什么

选择“界面设置”作为第一个代表性窗口，提出 **折光聚合与层叠展开** 的运动：从入口到完整窗口有清楚的形态生成、材质层次和内容交接，区别于整块淡入，也区别于把所有界面都做成球体回旋。

选择设置窗口是为了能对照现有真实组件、分类和关闭流程，不是未来只能小修一个窗口。方案如需要，可以改变视觉层次、控件运动和交互组织；是否扩展到其它窗口或更大规模重构由负责人决定。

## 可观察的分镜

| 场景 | 候选表现 | 负责人应能直接看见的差别 |
| --- | --- | --- |
| 输入回应 | 入口先产生清晰的压缩/折光反馈，一道细光脊连接入口和窗口落点 | 点击被回应，窗口的来源和落点可追踪，不是无反馈等待 |
| 窗口生成 | 斜向光脊推进，玻璃表面沿它折展成窗口；边缘、后层阴影与主面存在明确先后 | 窗口像被构建出来，有材质和空间，而非只改透明度 |
| 内容进入 | 标题/导航先建立层级，正文以分层的玻璃分页进入并稳定，余韵自然消失 | 有主次、加减速和完整落定，不让所有元素同拍出现 |
| 分类切换 | 保留窗口空间，旧内容沿导航方向翻折/退入后层，新页从共同交接线展开；焦点位置连贯 | 看出方向、前后关系和同一工作区里的连续换页，而非轻微横移 |
| 关闭 | 内容先归拢，主面沿原生成路径收束回入口；无有效入口时采用明确的窗口内收束 | 开与关有因果联系，结束有落点，不突然消失 |
| 中途反向 | 接续当前展开程度与运动方向，响应最新意图，不重播一长串过期完整动画 | 连续使用仍完整舒服，中断不会闪回起点或积压 |

以上是可供讨论的一种视觉方案，不是已验证的效果。不先给所有阶段规定固定毫秒上限；用原速完整表现判断演出价值，必要时允许合理功能等待。

## 响应、可用与余韵分开

- 输入回应从入口反馈开始，不把它推迟到整段演出结束。
- 内容/操作的可用时机由具体分镜决定。可在部分稳定后开放，也可为合理的视觉/状态交接短暂等待；等待必须有可见进展和理由。
- 关闭、再次点击与反向意图要单独定义，不让队列淹没最新意图。购买、保存等业务的重复/取消合同不得出错。
- 余韵可以与可操作阶段重叠，既不统一禁止功能等待，也不要求所有操作等到余韵结束。
- 真实控件与材质代理的运动组织暂不锁死，待方案确认后根据命中、键盘、固定后代坐标和交互阶段正确性决定。

## 旧版与候选怎样对照

1. 建议以公开3.0.4对应的实际窗口表现为主旧版输入，核对制品和源码身份；b507可作附加参考，不能把基础修整直接当成唯一“旧版”。具体输入先冻结记录。
2. 同一设备/浏览器、同视口、同缩放、同一操作序列；并排标清版本和输入时间，完整展示从输入到终态。不要求两边演出等长，不裁掉候选的等待，不加速制造流畅假象。
3. 分别展示首次打开、正常分类切换、连续切换、关闭、中途反向。桌面和一个窄屏各做原速对照；慢放仅作为补充观察材质与衔接。
4. 同时记录输入回应、内容/操作可用和余韵结束三个时点及实际限制，负责人据此判断“快速流畅、华丽精致、感知舒服”是否协同成立。

本轮按以上方法制作隔离候选与桌面/窄屏两组原速并排录像；具体实现、冻结身份、检查及限制见[原型说明](../../../prototypes/settings-refraction-v1/README.md)。没有接入实际游戏。

## 技术与可靠性怎样评估

不预先锁定WAAPI/GSAP/SVG/Canvas或新框架。方案获批后按实际表现收益比较运动组织、包体、维护成本、许可及宿主影响；不以CSS能做或依赖更多作为自动结论，不无证据宣布性能提升。

先盘点b507的隐藏页/卸载取消、代理所有权、旧回调清理、缩放换算，标记保留、适配或待验证。时长缩短和删去旋转/模糊不自动保留，也不机械回滚。若改动共享sourceMotion，列清属性、社交、普通面板、设置预览、OrbitFocus、商店、衣柜、战斗与天气等调用方的影响及验证范围。

原测试中针对“真实窗口不移动”的断言仅对应旧实现。若新方案批准控件运动，未来应验证正确命中/坐标和操作阶段，而不是让旧视觉选择永久封死方案；本次不改测试或运行代码。
