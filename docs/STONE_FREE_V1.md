# Soft & Wet UI 3.0 — Stone Free

## 产品基线与边界

以正式 2.6 为基础，继承现有悬浮球原型并补入 2.6 的缩放、浮层与战斗图组修复。保留原版和第三方 DOM、状态与事件所有权；功能可关闭，未知内容回退。UI API v1 不变。

发布底线 T0 是手机、平板和 PC 的代表性实际体验：手机触控、竖屏、IME；平板横竖屏、分屏和小窗口；PC 宽窄窗口及鼠标键盘。浏览器窄容器不替代物理手机证明。其余组合登记 coverage，不无限扩大验收。

## 阶段与当前进度（2026-10-13）

1. **自由悬浮球：已实现，跨设备覆盖继续收口。** 非模态入口、长按自由拖动、位置保存、扇形及网格共享 Tool ID 与执行逻辑。菜单外壳 Acrylic，内部按钮稳定。已通过桌面六种视口与键鼠、平板 trusted touch、真实手机 trusted touch 与 IME 避让；平板分屏、小窗口及手机横屏仍需代表性补测。

3. **剧情与动作分区：首轮研究完成，功能尚未实施。** 先研究原控件 sticky 和布局；只有动作身份、条件及 Outcome 可验证才考虑镜像。真正阅读／动作分离属于实验，不强接管未知页面。
4. **Widget 自由布局：首轮边界研究完成，原型尚未实现。** 默认关闭，只优先支持自有组件。不是全页面编辑器，不搬运未知业务 DOM。

阅读行高、段落间距、正文宽度，以及轻量强调色／密度／透明度按真实需要完善；不做主题市场、全局命令面板、无限编辑器、自动兼容所有 Mod 或 speculative 架构重写。

## 工具使用反馈

当前 Skill 实际解析到 Paisley Park 4.0.1，5.0 A/B 使用已存在的独立实验工具，没有假称全套 5.0 已安装。现成 CDP transport 与明确 serial / user / package / PID / socket / Document 绑定用于精确触控和状态检查，无 GER Store 更改。

- **问题：** 手机息屏时进程和 socket 存在，但调试连接超时。
  **场景／当前行为：** Dozing、NotificationShade；检查被拒或超时，包尚未写入。
  **期望／影响／建议：** 结合 power、真实 Window focus 判断可观察性。解锁前保留 Unknown，不将进程前台等同于可用现场；用户解锁后同一路径成功。这是环境状态，不是 UI 或 Tools 缺陷。
- **问题：** 固定 250ms 后读取菜单样式过早。
  **场景／当前行为：** trusted touch 已派发，probe 读取网格节点为 null；后续事件和 DOM 确认网格实际存在。
  **期望／影响／建议：** 等待目标状态而非只等派发 acknowledgement；增加有上限的 DOM 状态等待后通过。属于项目探针时序，失败保留，不登记为 Runtime 缺陷。

这些仅作真实反馈候选，不修改 Paisley Park 或为此增加采集平台。没有 Full Evidence、Perfetto、重装工具或完整游戏回归。
