# 原版优化存档兼容包 · 0.1.2

> 当前 2.2 构建的包版本与依赖见文末；此前版本说明保留为历史记录。
用于 **原版优化 1.1.1.2 + Soft & Wet 2.1.0 + DoL 0.5.12.13**。这是独立可选包，不包含原版优化或 UI 主包。

原版优化给存档增加了可编辑描述和游戏内日期。UI 主包会保留不认识的扩展槽位，但空槽进入新版卡片，容易出现两套列表。本包将已知结构切换为统一的原节点存档视图：宽屏双列轻卡片，窄屏单列；外层继续使用主包的 Acrylic。

## 保留什么

- 原存档节点、父子关系、顺序、id、控件值和事件。
- 原版优化的描述编辑、游戏内日期、分页和设置。
- 原保存、读取、删除按钮，不代理或重写存档业务。
- 未知内容与原 hidden 语义。版本、结构或浏览器能力不匹配时不启用此视图。

## 显示边界

兼容视图使用原槽位控件，暂不使用 UI 主包的搜索、槽位代理、详情 Drawer 或 V2 双栏详情。V2 偏好不被修改；禁用此包后恢复主包原显示。不会复制、删除、编辑或迁移存档。

通过 UI Runtime API 1 注册 Style Only Adapter，只添加可撤销的样式标记和 CSS；不搬节点，不改第三方函数，不新增业务状态。Inspector 中可查看 `DolOptimizationSoftWet` 的识别结果。

## 安装

先安装上述目标 Mod 与 UI 主包，再导入本包 ZIP（不要解压）并重载。仅使用匹配版本。关闭存档新版界面、关闭 Soft & Wet，或禁用本兼容包，均可退出兼容视图。

本包仅处理存档列表显示，不保证原版优化的所有其它功能。实机只读验收不会执行保存、读取或删除；描述写入与取消语义在隔离夹具中验证。

开发构建：源码为 `dol-optimization-soft-wet.ts`，仅以 `import type` 复用 UI 公共类型。运行 `python scripts/package-adapter.py compat/dol-optimization-soft-wet`，生成 JS 位于 `dist/scripts/dol-optimization-soft-wet.js`；ZIP 继续使用原 Manifest 的 JS 入口，不直接加载 TS，不捆绑 UI Runtime。类型迁移不改变存档节点、事件或数据。

## 验证

0.1.1 缩小卡片内边距及间距，摘要显示约两行并可滚动查看全文；空槽操作与标题并排，不再拉伸到相邻已保存卡片的高度。保留双列布局及至少 44px 的按钮触控高度。

0.1.2 将摘要排版同时应用到自动和手动槽位，避免只有可编辑 `.saveTitle` 节点得到新版样式。自动存档仍沿用原有按钮及编辑权限，不补造保存按钮。

`node tests/optimization-adapter.cjs PATH_TO_TARGET_OPT_MAIN_JS` 从目标 Mod 的源码提取实际 `initsave` 方法，在假存档中检查编辑取消和确认、原按钮事件、节点结构、额外日期、未知内容、hidden、版本/结构不匹配、原版回退开关、窄屏和清理。测试不读取真实存档。

### 补充检查 · 2026-10-06

- 平板检查了通用设置、原版优化设置入口、社交势力声望、日志与可用物品，以及存档分页和菜单重开。存档兼容样式在切换菜单后自动恢复；未执行真实存档读写、描述编辑或游戏动作。
- 原版优化设置中的原控件保留显示，无横向溢出。首次打开该设置页会由原 Mod 补齐默认选项；这不是兼容包维护的状态。
- 原版优化的全局 CSS 会把社交势力声望改为单列。实机内容仍可阅读和滚动，属于布局差异，本包未覆盖它。
- 原版优化 `initsave()` 在同一批节点上重复调用，会重复追加日期并再次绑定分页监听器。日期重复在移除本兼容包的隔离测试中同样出现；平板本轮正常分页和菜单重开未出现重复。本包不改写该方法。
- 原版优化为自己的快捷继续按钮添加循环扫光，与 Soft & Wet 的安静动效方向不同；当前页面没有该按钮，仅确认源码风险，未作实机判断。
- 可用物品的香烟和能量饮料图标未加载，回退原版日志后仍然缺图。原 ZIP 包含图片，且将图包注册到 BeautySelectorAddon；下一步需核对该图包的启用及图片加载情况，尚未确认根因。本包未修改图片或图片加载链。
- 自定义便利店、服装叠加及其它玩法未做流程验收，不将上述局部检查视为全部功能兼容证明。
